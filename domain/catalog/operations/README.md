# 운영 분야 합성 예제

각 JSON 파일은 ExampleSeed 배열이다. 서로 다른 운영 판단을 직접 작성하고, 제목·숫자·프레임워크를 바꾼 변형을 프로젝트 수로 늘리지 않는다. 입력과 규정은 합성 자료이며 실제 법률·회계·안전 기준을 대신하지 않는다. 모든 결과는 읽기·분석·사람 검토용이며 설비 제어, 송금, 주문, 계약 변경을 실행하지 않는다.

필드: id, title, category, pattern, problem, input, facts, output, rules(최소3), failures(최소2). 배치마다 필수 필드·ID·제목·업무 계약 중복을 검사한다. 실행 검증 상태는 루트 카탈로그 검증 도구가 별도로 관리한다.

현재 원본은 11개 작성 배치, 1,058개 계약이다. 제조·물류·구매·재무·식품·농업·시설·행사·문서·현장·생산·연구실 운영 외에도 교차 검토에서 확인된 중복을 인쇄, 전자 조립, 봉제, 목공·시제품의 별도 업무로 교체했다. 따라서 파일명은 최초 작성 배치 이름이고 실제 분류는 각 레코드의 `category`를 따른다. 기존 ID는 안정적으로 유지한다.

독립 에이전트가 원본을 읽고 비교한 결과는 `examples/catalog-reviews/technical-checks-operations.json`에 계약 해시와 함께 기록한다. 2026-10-22 확인 시 1,058건의 검토 해시가 현재 원본과 일치하고 미해결 반려는 0건이었다. 이는 인간 검수나 가능한 모든 예제 쌍의 의미적 무중복 증명이 아니다. 문서 및 합성 기대 결과 검토, Node.js·Python 내보내기 검증, 실제 외부 모델 검증은 별개 상태다. 이 원본 작성·정정 과정에서는 실제 모델이나 외부 업무 API를 호출하지 않았다.
