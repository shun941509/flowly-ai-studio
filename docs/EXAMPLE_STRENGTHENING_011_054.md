## 설정 위치

- OpenAI 모델은 웹에 등록하지 않는다. Node.js/Python ZIP의 `.env`에 `OPENAI_API_KEY`·`FLOWLY_MODEL`을 사용자가 직접 설정한다.
- 회사 MCP 정의는 ‘도구 및 자료’에 등록한다. 주소·토큰 값은 ZIP의 `.env.example`에 표시된 환경 변수에 설정한다. 정의만 등록하면 회사 서비스가 생성되는 것은 아니다.
- 두 실행기는 Python 3.11 이상이 필요하다. Node.js는 `FLOWLY_PYTHON`으로 지정하고, Python ZIP은 해당 환경의 `python`으로 실행한다.
- 044는 ZIP에 포함된 `flowly_triggers.py`의 `--help`를 따라 이벤트 수신기를 시작하고 `.env`의 `FLOWLY_TRIGGER_SECRET`을 설정한다. 수신기는 루프백에서 인증된 이벤트를 받는다. 회사 이벤트 전달 연동기는 별도로 설정해야 한다.
- 044의 `register_case_deadline`은 사건 ID·이벤트 ID·기한을 예약하고 영수증을 반환해야 한다. `send_case_reminder`는 같은 사건/이벤트 ID의 중복 발송을 방지해야 한다. 기한 이전 이벤트는 발송하지 않으며, 결과 불명확/승인 거절 이후의 예약은 자동 재발송하지 않는다. 운영자가 회사 서비스 상태를 확인해야 한다.
- 029는 이전 버전의 `transfer_stage` 원장도 읽는다. 내용이 남아 있으면 새 요청 예약과 외부 쓰기 전에 전환 필요 오류로 중단한다. 이전 원장만으로 덮어써졌던 과거 요청까지 복원할 수 없으므로 자동 삭제·초기화·불완전한 자동 이전을 하지 않는다. 운영자가 회사 서비스에서 요청별 결과를 확인한 뒤 별도 원장 전환을 해야 한다.

## 검증 구분

순수 Python 계산 테스트와 실제 TypeScript 엔진의 정상·경계 시나리오는 모델/MCP를 명시적인 테스트 응답으로 대체하고 실행한다. 계산·CAS·페이지·분기·승인·재개는 제품 코드를 사용한다. 제품 ZIP에 테스트 응답이나 자격 증명을 포함하지 않는다.

각 예제의 새 시나리오는 Node.js·Python 실제 ZIP CLI 통합 검사에도 사용한다. 최종 두 실행기의 결과는 통합 담당자가 현재 소스 지문으로 실행한 보고서를 기준으로 한다. 이 문서 작성 자체를 실제 ZIP 검증 완료로 간주하지 않는다. 이번 개발에서 실제 외부 OpenAI·MCP 호출은 0회이다.

최종 소스로 실제 ZIP을 생성·실행한 결과, 011은 12개, 014는 8개, 029는 16개, 042는 8개, 044는 14개, 054는 6개 양언어 시나리오를 통과했다. 합계 64개 시나리오와 언어별 설정 검사 12개이며 현재 증거는 `examples/workflow-verification.json`에 저장한다. 웹에서 키를 입력하거나 모델을 호출하지 않았다.

대량 처리 회귀에서 014의 페이지별 중간 결과를 여러 번 저장하는 비용을 확인했다. 페이지 내부는 입력→계산→완료 커서 저장→출력의 4개 노드로 줄였으며, 실제 항목 결과는 유지하고 커서와 출력 요약에 같은 행 전체를 다시 넣지 않는다. 최대 400개와 성공 항목 재사용 계약은 유지한다.

042의 작업 중 임대 만료 시나리오는 5초 임대를 갱신한 뒤 7초 작업으로 만료를 유도한다. 갱신 저장 1회·작업 Agent 1회·게시 0회·후속 Agent 0회를 확인하고, 다음 요청에서 revision 2를 기준으로 재점유한다. 저장이 느린 환경에서 1초 임대가 작업 시작 전 만료되던 테스트 전제를 수정한 것이며, 실제 시간에 따른 만료 정책은 완화하지 않았다.
