# 편집기·디자인·예제·내보내기 통합 구현

후속 하위 흐름 시각 편집·입출력 안내·예제 재사용·문서/Agent 실행 일치는 [범용 조합 P0~P4 기록](WORKFLOW_COMPOSITION_IMPLEMENTATION.md)을 확인하세요. 아래 수치는 이전 작업 시점의 기록입니다.

2026-10-25. 편집기, 내보내기, 예제 실행 계약을 병렬로 수정하고 공통 타입·권한·검증을 통합했다. 웹은 설계와 내보내기만 수행하며 OpenAI를 호출하지 않는다. 실제 회사 모델·MCP 서비스에는 연결하지 않았다.

## 편집기 조작

| 동작 | 구현 계약 |
| --- | --- |
| 마우스 휠 | 캔버스 안에서 포인터 아래의 좌표를 유지하며 3~160% 확대·축소. 패널 스크롤과 구분 |
| 화면 이동 | Space+드래그, 가운데 버튼, H/손 도구. V로 선택 도구 복귀 |

| 그룹 이동 | 선택한 블록의 상대 간격 유지. 좌표 한도에서도 그룹이 찌그러지지 않음 |

| 기타 | F2 이름 편집, Ctrl/Cmd+S 저장, ? 도움말, Esc 현재 작업 취소 |

입력창·선택 상자·편집 가능한 텍스트·모달·한글 조합 중에는 편집 단축키가 입력을 가로채지 않는다. 저장 단축키는 일반 필드에서도 사용할 수 있지만 모달과 한글 조합 중에는 제외한다. 선택과 보기 이동은 문서를 변경하지 않는다. 드래그 취소·화면 이탈은 임시 좌표와 변경 상태를 복원한다. 비동기 클립보드 읽기가 끝나기 전에 문서가 바뀌거나 다른 제스처가 시작되면 늦은 붙여넣기를 적용하지 않는다.

시작 블록 중복, 40개 블록·80개 연결 한도, 중첩 정의를 붙여넣기 전에 검사하며 실패 시 일부만 추가하지 않는다. 문서를 전환하면 이전 문서의 실행 취소 기록을 비운다. 패널을 열거나 창 크기가 바뀌어도 사용자가 정한 확대·이동 상태를 유지한다. ‘크게 보기’에서는 탐색 메뉴와 팔레트를 접어 설계 공간을 확보한다.

## 디자인

밝은 회색 작업 공간과 흰색 패널, 남색 주요 동작·선택 표시를 적용했다. Flowly의 초록 로고는 유지한다. AI·후보 탐색은 보라, RAG·기억은 청록, 도구·프로그램은 파랑, 병렬·팀·조정은 분홍, 분기·검토는 호박색으로 구분한다. 블록에는 아이콘·유형 이름·상단 색선을 함께 사용한다. 실행 성공·오류·대기 상태와 역할 색은 별개다.

예제 카드·필터·내보내기·설정 패널에도 같은 색 체계를 적용했다. 포커스 표시와 동작 줄이기 설정을 지원한다. 외부 Google Fonts 요청을 제거하고 운영체제의 한국어 글꼴을 사용한다. 기존 캔버스 구현을 재사용했으며 라이브러리는 교체하지 않았다.

## 네 가지 내보내기

| 항목 | 결과 | 조건 |
| --- | --- | --- |
| Node.js | 기존 실제 실행기 ZIP | 구조와 현재 자료 권한 검사 통과 |
| Python | 기존 실제 실행기 ZIP | 동일한 구조·권한 검사 |
| AI 명령 프롬프트 | 설계·분기·입출력·선택 자료·설정 안내를 미리 보고 텍스트만 복사 | 파일 다운로드 없음. 복사 API를 사용할 수 없으면 전체 선택과 수동 복사 안내 |
| Agent 다운로드 | 전용 Agent 진입점과 역할·Skill·MCP·실행기 ZIP, Node.js/Python 선택 | 최상위 또는 중첩 정의에 명시적 `agent` 블록이 있어야 함. UI와 서버 모두 검사 |

AI 답변·Skill·MCP만 있는 흐름은 Agent 다운로드를 활성화하지 않는다. 에이전트 팀·작업 조정이라는 이름만으로도 활성화하지 않으며 그 안에 실제 Agent가 있어야 한다. 이 규칙은 편집기·발행 버전·예제 직접 다운로드에 공통 적용한다.

Agent ZIP에는 다음이 포함된다.

- `Agent.md`, 호환 작업 규칙 `AGENTS.md`, `agents/role-NNN.md`
- 기본 실행 Skill과 선택한 자료의 `skills/.../SKILL.md`
- `AI_PROMPT.md`, `WORKFLOW_GUIDE.md`, `START_HERE.md`
- `workflow.json`, `mcp.json`, `agent-manifest.json`
- Node.js `agent.mjs`·`runner.mjs` 또는 Python `agent.py`·`runner.py`
- `.env.example` 및 필요한 등록 Python 도우미

전용 Agent 진입점은 고정된 설계·실행기·MCP 정의 파일을 검사한 뒤 전체 워크플로를 실행한다. 다른 설계 파일을 선택하는 우회 옵션은 받지 않는다. 설정 값은 `.env`로 공급한다. 지침 문서가 승인·권한·실행 한도를 대체하지 않으며 숨겨진 사고 원문을 요구하지 않는다.

프롬프트와 모든 ZIP은 같은 인증·자료 접근 검사와 크기 한도를 적용한다. 공유가 철회된 자료의 새 복사·다운로드는 거절한다. 이미 내려받은 복사본을 원격 회수하는 기능은 없다. 원본 변경이 필요하면 다시 내보내야 한다. 자료에 들어 있는 명령문은 업무 데이터로 구분한다. 키·토큰 원문과 `.env`, 테스트 대역은 ZIP에 넣지 않는다.

대량 처리 검사 중 발견한 실패도 수정 대상으로 다뤘다. 014의 페이지 내부 중복 저장을 줄였고, 400항목의 정상 공개 실행 기록이 400만 글자를 넘는 것을 확인하여 검증기의 출력 수집 상한을 1,600만 글자로 조정했다. 500만 글자 정상 JSON과 상한 초과 중단을 별도로 검사하여 관련 검증기 회귀 14개를 통과했다. 제품 실행 한도를 늘려 통과시키지는 않는다. 042는 작업 시작 전 만료되던 1초 테스트 임대 대신 갱신 후 작업 중 만료를 명시적으로 검증한다.

Python의 400항목 검사는 실제 120초 실행 한도에도 도달했다. 체크포인트 전체를 저장할 때 반복되는 문자열·필드명 마스킹 비용을 줄이도록 `redact`를 개선했다. 256자 이하 문자열과 민감 필드명 판정만 각각 최대 2,048개까지 한 호출 안에서 재사용하며, 다음 저장에 캐시나 비밀 값을 넘기지 않는다. 긴 문자열과 캐시 한도 이후 입력도 계속 검사한다. 원자적 저장·fsync·잠금·실행 한도는 유지한다. 이전 결과와 동일성, 호출별 비밀 값 변경, 키 충돌, 캐시 초과, 긴 입력, 원본 불변의 6개 회귀를 통과했다.

최종 014 ZIP 재검사에서는 두 언어의 8개 시나리오와 설정 검사 2개가 모두 통과했다. 400개 입력과 실패 항목 보완, 완료 결과 재사용, 완료 후 재개 시 재계산 없음이 포함된다. 이 증거는 최종 전수 검사의 같은 소스 지문·설계·ZIP 해시 확인을 거쳐 재사용한다.

최종 전수 검사는 014의 현재 증거 1건을 재사용하고 나머지 226개를 다시 실행했다. 전체 227개에 대해 현재 소스 지문·설계 해시·모든 시나리오·두 ZIP의 해시 일치를 확인했다. 집계 명령 `complete-example-catalog.ts`는 `sourceEvidenceComplete=true`이며, 종료 코드 1의 유일한 이유는 과거 AI Agent 3,200개 목표가 미달이기 때문이다. 현재 공개 Agent는 156개로, 남은 3,044개를 구현 완료로 표시하지 않는다. 실행 검증 실패와 목표 수 미달을 구분한다.

브라우저 도구의 가상 클립보드와 페이지의 Clipboard API가 분리되어 도구로 복사 원문을 다시 읽는 검사는 수행하지 못했다. 실제 페이지의 복사 완료 응답과 복사 실패 시 선택 대체 동작의 테스트를 구분해 기록한다. 사용자의 저장된 설계는 UI 검사 후 원래 상태로 복원했으며 검증 중 임시 편집은 저장하지 않았다.
