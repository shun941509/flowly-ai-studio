## 검증 방법

`pnpm catalog:audit`는 ID·제목·설명·프롬프트·좌표를 제거하고 방향 그래프, 노드 종류, 분기, 중첩 흐름을 비교한다. 실행 설정 판정은 데이터 매핑, 스키마, 조건, 도구 설정 등을 추가 비교한다. 끊어진 장식 노드나 비교 한도를 초과한 그래프는 거절한다. 서로 다른 구조가 유용성이나 모델 답변의 정확성을 자동으로 증명하지는 않는다.

`pnpm test:examples`는 개별 설계의 실제 Node.js/Python ZIP CLI를 실행한다. 정상·경계·실패 시나리오별 결과와 실제 실행/건너뜀 이벤트(중첩 포함), 모델로 전달한 데이터, 검토 수정·수락·거절·재개, 이전 실행의 기억을 검사한다. 테스트 전용 HTTP 응답은 ZIP 밖에서 주입하며 다른 네트워크를 차단한다. 부모 환경의 모델 키를 전달하지 않고 제품 ZIP에 테스트 응답을 포함하지 않는다. 새 결과는 `examples/workflow-verification.json`, 산출물은 `outputs/workflows/`다.

`--resume --workers 2`는 현재 실행기 지문·개별 설계/실행 해시·설정 검사·전체 시나리오·두 ZIP 해시가 모두 맞는 성공만 재사용한다. 새 배치를 추가해도 이전 배치의 증거는 이 기준을 통과하면 유지하고, 공통 실행기나 하네스가 바뀌면 전체를 다시 실행한다. `--ids`와 `--prefix`로 수정한 항목을 먼저 검사할 수 있다. 실패한 CLI 인자·출력과 상태는 `outputs/workflows/.validation-*`에 남는다. 현재 UI 배지도 동일한 증거와 실제 ZIP 해시를 검사하며 실패 기록이 남은 ID는 제외한다.

이번 확장 중 Windows의 일시적인 상태 파일 교체 `EPERM`을 실제 ZIP 실행에서 발견했다. 같은 임시 파일 교체만 최대 6회·총 대기 620ms 이내에 재시도하며 매회 저장소 잠금을 확인하도록 고쳤다. 외부 도구 호출이나 작업 자체를 반복하지 않는다. 디스크 부족·파일 없음 등 다른 오류와 POSIX 오류는 즉시 실패한다. 소유권 상실·영구 오류·횟수 한도 회귀 검사를 추가했다.

`pnpm catalog:complete`는 현재 구조·소스 지문·ZIP 해시를 확인하며 3,200개 목표가 충족되지 않으면 완료 처리하지 않는다. 부분 집계는 [현재 집계](EXAMPLE_CATALOG_INVENTORY.md)를 따른다.

## 실제 연결

웹 OpenAI 호출은 차단한다. 이 작업에서 실제 OpenAI·원격 MCP·외부 쓰기 호출과 기존 키 접근은 0회다. 모델이 필요한 예제는 사용자가 내보낸 폴더에 본인의 키와 모델명을 설정하기 전까지 미설정이다. 합성 자료를 사용하는 예제는 실서비스 조회로 표시하지 않는다. 실모델 답변 품질, 실제 계정 연결, 운영 SSO·배포 검증은 미완료다.

정책 버전 선택은 날짜 형식을 검증한 후 AI 분류로 결정한다. 결정적 날짜 범위 계산의 정확성을 보장하는 기능은 아니다. 실제 모델 분류 품질은 별도 평가가 필요하다. 공개 목록은 모든 항목의 실제 실행 구조를 비교한다. 서버 초기화에서도 같은 구조를 거절한다. 사례 조회(view=cases)는 410, 이전 사례 ID의 조회·복제·두 언어 다운로드는 404로 차단한다.

추가 회귀 검사에서는 복제된 문서의 새 ID를 실제 검색 결과에서 읽어 인용을 검사한다. 최초 제작 원문은 사람이 시안을 수정해도 보존하며, 검토자의 변경값만으로 일치 검사를 우회할 수 없다. 마스킹 결과를 최종 자료에 전달하고, 회피 신고·인물 특징·배포 동의 검토에는 원자료를 함께 전달한다. 운영 예제는 실제 배포·삭제·전송을 실행하지 않는 판정 흐름임을 명시한다. 알림 예제의 기억은 마지막 1회차에 한정하며 전체 이력의 중복 검출로 표시하지 않는다.
