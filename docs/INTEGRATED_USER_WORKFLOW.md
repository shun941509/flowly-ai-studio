# 통합 사용자 흐름 구현 명세 · 2026-10-26

이 문서는 이번 통합 작업의 현재 계약이다. 이전 IMPLEMENTATION_PLAN과 실행 기록은 당시의 기록이며, Agent 다운로드의 Agent 필수 조건과 워크플로 소유자 전용 조회 규칙은 아래 규칙으로 대체한다. 과거의 실제 서비스 검증 또는 전체 예제 검증 수치를 이번 변경의 검증으로 간주하지 않는다.

## 제품 경계

- 웹: 한국어 설계, 자료 관리, 검사, 규칙 기반 설명·미리보기, 공유, 내보내기·가져오기. OpenAI 호출과 API 키 입력 없음.
- 내려받은 프로젝트: 사용자가 자신의 PC에서 모델·사내 MCP 설정 후 실행. Node.js/Python 모두 기존 실행 엔진과 지속 상태 저장을 사용.
- Cowork·Codex: 복사한 작업 지시와 다운로드한 프로젝트를 전달받아 수정·검증·실행하는 외부 작업 도구. 웹이 대신 해당 제품에 명령을 보내지 않음.
- MCP 정의는 ‘도구 및 자료’에서 관리한다. 주소·인증 비밀 값은 다운로드한 환경의 `.env`에 설정한다. 네트워크 주소 허용 목록은 추가하지 않는다.

## 공통 계약과 파일 책임

| 담당 영역 | 변경 경계 |
|---|---|
| 통합 | `Workflow`의 선택적 ACL 메타데이터, `workflow-access`, D1 추가 마이그레이션, 저장·공유·이력 API, Studio 통합 |
| A | 편집기·하위 편집·가이드·입출력 도움말·예제 설명과 맞춤 설정 |
| C | 내보내기·AI 작업 목적·공통 문서·파일 일치 검사·외부 수정본 파서와 대화상자 |
| D | 다운로드한 로컬 운영 화면·설정·파일 입출력·지속 실행 운영·두 실행기 검증 |

`Definition` 버전 1~5 및 기존 마이그레이션은 유지한다. 웹 `flowly-workflow`와 실행 프로젝트 `flowly-executable-export`를 명시적으로 구분해서 읽는다. 가져온 원본 메타데이터는 권한의 근거가 아니다.

## 구현된 사용자 흐름

1. **가이드 확인**: 처음 시작하기 / 핵심 용어 / 사용 방법과 문제 해결. 모든 블록과 Agent·MCP·Skill·Prompt·RAG의 뜻·용도·설정 위치·예시·차이·현재 지원 범위를 한 공통 소스로 제공한다. 도움말은 편집 내용을 유지하는 모달이며 내보낸 `CORE_TERMS.md`에도 같은 설명을 사용한다.
2. **예제 복제**: 모든 로그인 사용자가 공통 Agent·보조 예제를 조회·복제한다. 원본과 기존 사용자의 자료는 변경하지 않는다. 사본과 함께 복사하는 합성 자료는 새 사용자의 비공개 소유이다. 서비스 미설정은 복제를 막지 않는다.
3. **예제 맞춤 설정**: 목표 → 자료 → 역할 → 결과 → 완료 조건. 실제 하위 Agent의 지침도 변경한다. 자동 판정 블록이 없는 설계에 가짜 판정 기능을 추가했다고 표시하지 않고 해당 블록 추가·편집을 안내한다.
4. **설계 수정**: 기본/고급 설정, 실제 반환 필드와 예시 입력, 필수 값·자료형·분기 누락 안내, 그래프에 따른 실행·실패 경로 설명, 실제 중첩 블록으로 오류 이동. 적용 전 하위 초안과 미완성 JSON은 사용자·워크플로·하위 경로별로 보관·복구한다.
5. **공유 설정**: 내 워크플로에서 읽기/수정 범위와 마지막 수정자 표시. 공유 워크플로에서 나에게 공유됨 / 함께 편집 / 전체 공개 조회. 조회 전용 캔버스는 탐색을 허용하고 설계 변경을 막는다.
6. **외부 AI 전달**: AI 명령 프롬프트는 복사 전용이다. ‘설계대로 실행 / 수정 후 실행 / 프로젝트 구성’ 목적을 선택하고 짧은 시작 지시와 전체 지시를 구분한다. Agent 다운로드는 Agent 유무와 무관하게 제공하며 가짜 Agent를 삽입하지 않는다.
7. **로컬 실행과 결과 확인**: 첫 실행 확인, 사용자 PC의 연결 설정, 입력 양식·파일 업로드, 새 실행, 진행 상태, 승인 내용, 중지·재개, 결과 파일 다운로드. 고급 운영 명령은 보존한다.
8. **수정본 가져오기**: JSON 또는 ZIP 선택 → 원본·발행 버전·수정 기준 확인 → 변경 비교 → 접근 가능한 자료로 재연결 → 검증 → 비공개 새 사본 또는 원본의 새 버전. 실행 기록과 승인 객체를 이관하지 않고 새 실행으로 시작한다.

## 권한 모델

| 동작 | 소유자 | 조회자 | 지정 편집자 | 권한 없음 |
|---|---|---|---|---|
| 설계 조회·내보내기 | 허용 | 허용 | 허용 | 거절 |
| 블록 추가·수정·삭제, 저장·새 버전 | 허용 | 거절 | 허용 | 거절 |
| 워크플로 자체 삭제 | 허용 | 거절 | 거절 | 거절 |
| 읽기·수정 권한 관리 | 허용 | 거절 | 거절 | 거절 |

- 읽기: 나만 / 지정 사용자 / 전체 로그인 사용자. 수정: 나만 / 지정 사용자. 전체 수정은 서버가 거절한다.
- 수정 권한은 읽기를 포함한다. 비소유자에게 공유 대상 이메일 목록을 반환하지 않는다. 수정 범위만 보여준다.
- 클라이언트 ownerId·ACL·역할은 저장 소유권을 결정하지 않는다. 검증된 세션을 사용한다.
- `0003_workflow_sharing.sql`은 기존 데이터에 비공개 기본값만 추가한다. 로컬 DB는 적용 전에 `work/backups/`에 백업했다.
- 저장·권한 변경·외부 수정본 반영은 `updatedAt` 조건부 갱신을 사용한다. SQL 변경 시점에도 현재 편집 권한을 확인한다. 외부 새 버전은 설계·스냅샷·감사 기록을 한 D1 트랜잭션으로 저장한다.
- 현재 권한을 조회·저장·발행·내보내기에서 재검사한다. ZIP 생성 뒤에도 자료와 워크플로 권한을 다시 확인한다. 공유 회수는 다음 요청부터 차단하며 이미 다운로드된 파일은 원격 회수하지 않는다.
- 워크플로 공유는 MCP·Skill·Prompt·Document 접근 권한이나 자격 증명을 추가하지 않는다. 해당 자료는 별도 공유 또는 내 자료로 재연결해야 한다.

## 내보내기·수정·가져오기 계약

- 프로젝트 이름·원본 ID·설계 버전·발행 버전(있을 때)·내보낸 날짜를 구분한다.
- `START_HERE.md`, `AI_START.md`, `AI_PROMPT.md`, `AGENTS.md`, `Agent.md`, 선택한 Skill·자료·MCP 정의, `workflow.json`, 실행기와 설정 예시, 작업·검증 가이드가 같은 manifest를 사용한다.
- 실제 키·토큰·로컬 `.env`·이전 실행 상태는 내보내지 않는다.
- `PROJECT_FILES.json`과 `project-check.py`는 파일 변경을 확인한다. 외부 AI는 `ROUNDTRIP.md`에 따라 변경을 기록하고 설계 수정본을 웹에 가져온 후 문서·실행기를 다시 내보낸다.
- 임의 실행기 코드 수정은 별도로 표시한다. 코드 변경을 자동으로 노드 설계로 복원하거나 안전하다고 인증하지 않는다. 가져오기는 ZIP 코드를 실행하지 않는다.
- 출처 버전이 현재 저장본과 다르거나 수정 권한이 없으면 새 버전 덮어쓰기를 허용하지 않는다. 새 사본 경로를 이용해 비교·통합한다.
- 새 사본은 비공개이고, 외부 파일의 자료 본문·ACL·계정·연결 비밀 값을 자동 등록하지 않는다.

## 사용자 환경에 남는 설정과 지원 경계

- 실제 SSO 제공자 설정과 운영 D1 마이그레이션 적용은 배포 환경 담당자가 진행해야 한다. 이번에는 로컬 D1과 고정 테스트 계정만 사용했다.
- 처음 한 번 Node.js/Python 및 예제에 필요한 선택 의존성 설치가 필요하다. 설치 후에는 로컬 운영 화면에서 일상 입력·승인·결과 확인이 가능하다.
- 모델을 사용하는 설계는 내려받은 폴더의 `.env` 또는 로컬 설정 화면에서 `OPENAI_API_KEY`, `OPENAI_MODEL` 등을 설정한다. 필요한 MCP 변수 이름과 선택 의존성은 해당 프로젝트의 시작 안내·설정 확인에 표시된다.
- 실제 모델의 답변 품질, 회사 MCP의 가용성과 실제 외부 변경 효과는 이번 검증에 포함하지 않는다. 테스트 대역 결과는 실제 서비스 실행 결과가 아니다.
- 메모리·RAG·ToT/GoT·DB 등은 현재 등록된 프로그램·블록·실행기의 지원 범위에 따른다. 임의 코드/SQL 실행이나 범용 기능 전체를 완성했다고 표시하지 않는다.
