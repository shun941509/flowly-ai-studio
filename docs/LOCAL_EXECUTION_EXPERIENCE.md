## 구현 내용

- 첫 실행 준비: 필요한 OpenAI 모델·키, MCP 주소·토큰 항목을 설계에서 찾아 표시합니다. 키·토큰은 선택한 로컬 `.env`에만 저장하고 다시 반환하지 않습니다. 기존 비밀 값은 빈칸 저장으로 지워지지 않으며 다른 환경 변수도 보존합니다. 대기·실행 중에는 설정 변경을 차단합니다.
- 설정 확인과 연결 점검 분리: `check`는 로컬 파일·환경·의존성을 검사합니다. 실제 서비스 연결 점검은 고급 메뉴에서 사용자가 직접 선택할 때만 실행합니다. 자동 새로고침과 설정 저장은 모델·MCP를 호출하지 않습니다.
- 쉬운 입력: 시작 Form의 숫자·예/아니요·목록·날짜·파일 필드를 화면에 표시합니다. 일반 입력은 요청 문장으로 받습니다. 고급 JSON 입력도 유지합니다.
- 파일 선택: 인증된 로컬 업로드로 10MB 이하 파일을 `inputs/uploads/<고유 폴더>/`에 저장합니다. 원본과 기존 업로드를 덮어쓰지 않습니다. 입력과 보완 입력 Form의 file 필드에 상대 경로를 연결합니다. 일반 입력에서 파일 선택 시 해당 경로가 요청으로 들어가므로 설계의 파일 입력 매핑을 확인해야 합니다.
- 새 실행 시작: 오프라인 설정 검사를 통과한 뒤 지속 대기열 등록과 처리기 시작을 한 동작으로 연결합니다. 재개도 같은 사전 검사를 수행하며 미설정이면 필요한 항목을 안내하고 대기열을 만들지 않습니다. 승인·거절·보완 입력 저장은 실행을 자동 재개하지 않으며 **이어서 실행**에서 같은 실행의 저장된 완료 단계를 이어갑니다.
- 결과 확인: 실행 상태·다음 행동·답변·오류를 상세 JSON과 분리합니다. 승인 대상 도구·인자·기한을 표시합니다. 이 실행의 기록에 연결된 `outputs/` 결과 파일을 다운로드할 수 있습니다. 임의 경로와 환경 파일은 다운로드할 수 없습니다.
- 중지: 기존 협력적 취소와 불명확한 외부 쓰기의 자동 재실행 금지를 유지합니다. 새 실행은 이전 실행 ID·승인·기록과 구분합니다.

프로필·우선순위·대기열·평가·백업·복원·비용 등 고급 운영 기능은 유지합니다. 초기 로컬 서버 시작과 Python/Node.js·선택 의존성 설치는 아직 사용자 환경에서 필요합니다. 설치형 데스크톱 앱이나 모든 운영체제의 자동 설치 기능은 구현하지 않았습니다.

## 병렬 통합 검사의 시간 의존성 보강

병렬 CPU 부하에서 나타난 두 검사 실패를 재현 분리했습니다. 상위 실행 시간 한도 검사는 실제 경과 시간 오차 허용치를 늘리는 대신 가상 Date/타이머에서 **남은 90ms에 정확히 중단**되는지 검사합니다. 병렬 모델 테스트 경계는 지정한 형제 호출이 실제로 모두 도착할 때까지 최대 10초 기다립니다. 실제 호출 시간 중첩 단언을 유지하며 순차 실행으로 퇴행하면 이 대기에서 실패합니다. 제품 실행기 코드는 바꾸지 않았습니다.

두 실패 항목을 낮은 동시성으로 다시 실행해 일반/Agent × Node.js/Python의 병렬 경로와 상위 시간 한도 검사가 통과했습니다. 이 재검사 결과를 전체 카탈로그 재검사 완료로 확대하지 않습니다.
