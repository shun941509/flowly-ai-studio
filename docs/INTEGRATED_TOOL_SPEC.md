# 195개 후보·100개 기획 통합 기능 명세

이번 작업은 P0~P4를 별도 승인 단계로 나누지 않고 공통 계약·Python 도구·실행기·내보내기·예제·화면을 병렬 개발하는 하나의 범위로 다룬다. 기능을 목록에 추가하는 것과 업무 계약 전체가 실제 동작하는 것은 구분한다.

## 기준 목록과 구현 경계

- `domain/tool-catalog.json`: 후보 195개, 기능군13개, 기획001~100. 후보 ID는 한 번씩 존재한다.
- `scripts/build-tool-catalog.mjs`: 원본 후보와 역사적99개 기획에서 대응표를 재생성한다.
- [전체 후보 대응표](TOOL_CANDIDATE_MAP.md), [100개 기획 대응표](EXAMPLE_100_IMPLEMENTATION_MAP.md).
- 기획100개, 현재 공개 소스 설계 수, 과거3,200개 목표는 서로 다른 집합이다. 이름·프롬프트 변형을 새 워크플로 완료 실적으로 집계하지 않는다.
- 현재 소스 143개 중 명시적 Agent를 포함한 72개를 기본 AI Agent 예제로 보여 준다. 나머지 71개는 계산·기존 보조 흐름 탭에 보존하며 AI Agent 예제 수에 더하지 않는다. 하위 작업에 있는 Agent도 검사한다.
- 이번 통합에서 29개 기획에 서로 다른 대표 실행 그래프를 추가했다. RAG 갱신·철회·복구와 ToT·GoT 기존 5개에는 결과를 승인하거나 보류하는 독립 Agent 검토를 보강했다. 기획 100개의 전체 완료를 의미하지 않는다.
- 추천된 도구 ID는 실행 권한이 아니다. 실제 그래프의 프로그램 또는 Agent 허용 목록에서 선택한 도구만 내보낸다.

## 실행 계약

기존 계산·검증 프로그램6종은 보존한다. 새로운 `python_tool` 프로그램은 `{toolId,arguments}`를 사용하고 도구 ID를 고정한다. 바인딩은 `arguments`의 값만 전달한다. Agent의 `pythonTools`는 별도 명시적 허용 목록이며 MCP 허용 도구와 합산한 한도를 따른다. 자동으로 임의 Python 파일이나 업로드 코드를 실행하지 않는다.

Python 계산 결과는 기존 프로그램과 같은 `{text:정규화된JSON,data:결과}` 계약으로 전달된다. Node.js는 포함된 Python 작업 프로세스를 호출하고 Python 실행기는 같은 구현을 사용한다. Node와 Python의 실행 기록 저장 형식은 다르므로 언어를 바꾸어 체크포인트를 이어 실행한다고 안내하지 않는다.

도구 레지스트리는 허용된 함수 ID만 실행한다. 입력 크기·배열 수·행렬·모델 모수·파일 경계를 검사하고 의존성·모델·실행 오류를 구분한다. 내보내기 `check`는 필요한 의존성·로컬 모델·엔진·설정 상태를 검사하며 자동 다운로드나 외부 서비스 탐색을 하지 않는다.

## 웹·설정·공유

웹은 모델 키를 받거나 OpenAI를 호출하지 않는다. 실제 모델·사내 MCP는 내보낸 환경에서 사용자가 설정한다. MCP 정의는 도구 및 자료의 기존 등록·공유 구조를 사용한다. 회사 네트워크의 주소 제한을 별도 허용 주소 목록으로 중복 구현하지 않는다.

Python 도구 설정 자료는 Document의 `flowlyPython` 구조로 저장해 기존 자료 권한과 공유를 재사용한다. 키·토큰은 포함하지 않는다. 자료를 프로그램으로 추가할 때 원본 resourceId를 보존하여 자료 사용 권한 검사를 유지한다. 이미 내보낸 오프라인 복사본을 원격 회수할 수 있다고 안내하지 않는다.

설정 위치는 ZIP의 `.env.example`을 복사한 `.env`다. `OPENAI_API_KEY`, `FLOWLY_MODEL`, MCP 연결별 주소·토큰 변수, 필요 시 `FLOWLY_PYTHON`을 지정한다. 로컬 도구는 모델 파일·엔진·패키지를 별도로 준비한다. 미설정 모델에 가짜 응답을 반환하지 않는다.

## AI 문서와 패키지

`AI_PROMPT.md`, `AGENTS.md`, `WORKFLOW_GUIDE.md`, `skills/flowly-workflow/SKILL.md`는 동일한 워크플로·자료·허용 도구에서 생성한다. 도구 manifest는 ID·버전·입출력·의존성·모델 요구사항·실행 범위를 안내한다. Markdown 문서의 지침은 실행기의 권한·승인·한도를 덮어쓸 수 없다.

내보낸 프로젝트에는 선택한 도구 계약과 공통 Python 실행 코드, 필요한 의존성 안내를 포함한다. 사용자 키·테스트 모델 응답·테스트 선행로드 파일을 포함하지 않는다. 테스트 어댑터는 검증 프로세스 밖에서 주입한다.

## 실제 지원 범위의 표시

195개 제목은 넓은 기술 영역을 포함하므로 지원하는 범위를 도구 설명에 명시한다. 예를 들어 ANN의 기본 구현은 정확 최근접 기준선이고 HNSW가 별도 근사 색인이다. 객체 탐지는 임계값 연결 성분 범위, 화자 분리는 음향 프레임 군집 범위다. RPA·컴퓨터 사용은 제공한 격리 HTML의 제한된 동작이며 일반 데스크톱 제어가 아니다. 콘텐츠 자격 증명·워터마크는 Flowly HMAC 프로토콜이며 C2PA 또는 범용 AI 생성물 판별이 아니다.

개인정보 패턴 가림은 완전한 비식별화가 아니며, 단일 Laplace 질의는 누적 개인정보 예산 관리가 아니다. 모델 설명 도구는 공개 수치·특징 기여를 반환하고 모델의 내부 사고 원문을 수집하지 않는다.

## 검증과 남은 업무 계약

`tests/tool-catalog.test.ts`는 195/13/100의 무중복 연결·명시적 허용 목록·Agent 포함·구조 차이를 검사한다. `tests/workflow-export-integration.ts --prefix integrated-`는 실제 ZIP과 두 CLI 프로세스를 사용한다. 로컬 알고리즘을 실제 실행하며 모델·MCP HTTP만 테스트 경계로 차단·주입한다. 최종 전체 그래프 실행 결과는 `examples/workflow-verification.json`에 기록한다. `integrated-*-verification.json`은 개발 중 부분 재검사 자료이므로 중간 실패·이전 런타임 지문이 남아 있을 수 있다. 최신 전체 보고서의 지문·실패 수와 생성 시각을 확인한다.

대표 경로와 전체 기획 완료는 구분한다. 분산 작업 점유, 목표 변경에 따른 전면 무효화, 모든 개발·DB 업무 계약, 모든 RAG 수명주기의 통합은 대응표에 남은 작업을 명시한다. 도구 함수가 존재한다는 이유로 이러한 업무를 완료 처리하지 않는다. 실제 모델 품질·사내 MCP·운영 배포는 이번 외부 서비스 없는 검사로 검증되지 않는다.
