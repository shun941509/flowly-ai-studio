## 실행 증거의 해석

프로그램 노드는 자체 계산·검증을 실제로 수행한다. P4의 합성 검사 도우미는 임시 폴더에서 고정된 Python 시험과 SQLite 작업을 실제 수행한다. 이 도우미는 제품 ZIP에 포함하지 않으며, 내보낸 P4 프로젝트에는 사내 MCP의 도구 계약만 포함한다. 사용자는 ‘도구 및 자료’에 회사 서비스 구현을 등록하고 ZIP의 `.env`에서 정확한 주소·토큰 변수를 채운다. 범용 샌드박스가 내장되었다고 표시하지 않는다.

모델 응답과 MCP 전송은 외부 서비스에 접속하지 않는 테스트 경계로 검사한다. 웹은 OpenAI를 호출하지 않는다. 로컬 파일·DB·프로세스에서 실제 작업했다는 사실과 실제 OpenAI·사내 MCP 실계정 연동을 구별한다. 이번 검증의 실제 외부 OpenAI·MCP 호출은 0회다.

P3의 재사용은 동일한 등록 작업 정의와 입력의 완료 결과를 다시 이용하는 기능이다. 자료 변경으로 어떤 산출물을 무효화할지 분석하거나 동적 방식의 새 작업 계약 생성과는 별도이며 일반 산출물 변경 영향 분석은 남아 있다. 완료 조건을 통과하지 못하면 모델이 완료를 선언해도 성공으로 바꾸지 않는다. 결과가 불명확한 외부 쓰기는 자동 재실행하지 않는다.

## 독립 검토에서 확인한 수정 지점

- 개발 단계의 리뷰 거절이나 시험 실패가 단순한 정상 종료 산출물로 전달되어 DB 변경을 계속할 수 있는 경로를 확인했다. 실제 시험 결과를 모델 검토 앞에서 검사하고, DB 진입도 개발 산출물의 `testsPassed`로 차단하는 경로와 0회 변경 검사를 추가하도록 수정했다.
- 이미 수락한 사람 검토를 기한 이후 재개할 때 Node.js와 Python의 해석이 달랐다. 기한은 대기 중 결정에 적용하고 기한 안에 저장한 결정은 재개 시 보존하는 규칙으로 맞췄다. 외부 쓰기 승인의 실행 만료 정책과는 별개다.
- 중첩 보완 입력의 만료는 루트·요청 실행뿐 아니라 중간 상위 실행의 상태에도 반영해야 한다. 전체 경로의 만료 상태 일치 검사를 보강했다.
- P3에서 추가한 작업 `dependsOn`이 AI 문서 요약에서 빠진 것을 확인하고, 실제 manifest의 의존 관계와 완료 조건을 문서에 그대로 포함하도록 수정했다.

문서와 Skill은 실행 지침이며 권한 검사기나 비밀 저장소가 아니다. 등록 Skill 원문은 안전한 경로·YAML 문자열·JSON 코드 블록으로 보존하고 선택하지 않은 자료를 포함하지 않는다. 사용자의 실제 비밀 값은 로컬 `.env`에만 등록하며, 문서 내보내기는 환경 변수 원문을 읽지 않는다. 모델의 비공개 사고 원문을 요구하거나 저장하지 않는다.

후속 단계의 최신 증거와 상세 범위는 [동적 Agent·RAG·후보 탐색 구현 기록](DYNAMIC_RAG_SEARCH_IMPLEMENTATION.md)을 따른다.
