# 자료·편집기·내보내기 통합 구현

2026-10-27. 첨부 작업 지시서와 개발자 설명 주석을 함께 적용한 기록이다. 이전 문서의 테스트 통과 수는 이번 구현의 증거로 사용하지 않는다. [공통 계약](RESOURCE_EXPERIENCE_CONTRACT.md), [코드 읽기 안내](CODE_READING_GUIDE.md), [Python 활용 항목 소스 대조](PYTHON_TOOL_SUPPORT_AUDIT.md)를 함께 읽는다.

## 구현한 사용자 흐름

1. 가이드에서 시작하기·핵심 용어·블록 가이드·문제 해결을 확인한다. 블록 설명은 화면과 내보내기 문서가 같은 데이터를 사용한다.
2. 예제의 목적·입력·진행 순서·결과를 넓은 상세 창에서 확인해 복제한다. 프레임워크 필터와 태그를 제거했으며 실행 원본·호환 정보는 유지했다.
3. 자료 본문과 유형별 정의, 필요한 첨부를 등록한다. MCP는 주소/토큰 **변수 이름**과 도구 입출력 계약을 기록한다. 실제 값은 웹에서 받지 않는다.
4. 편집기의 기본/자료·도구/입출력/고급 탭에서 블록을 조합한다. 복수 선택에는 검색·필터·선택만 보기·한도·누락 안내를 사용한다. 단일 선택과 필수 체크의 의미는 유지한다.
5. 운영용 Node.js/Python 프로젝트 또는 Agent 프로젝트를 받거나 Cowork/Codex 지시를 복사한다. Agent 블록이 없어도 다운로드한다. 문서·자료·파일·실행기·검사 스크립트는 같은 manifest를 사용한다.
6. 로컬에서 연결과 의존성을 설정한다. 사용자가 선택한 Skill 코드를 승인하여 실행하고 결과를 확인한다. 웹은 모델·MCP·업로드 코드를 실행하지 않는다.
7. 외부에서 수정한 ZIP/JSON을 다시 선택해 설계·자료·파일·실행 코드 변경을 구분한다. 자료 원본을 자동 덮어쓰지 않으며 공유 자료는 내 비공개 사본으로, 소유 자료는 충돌 확인 후 새 버전으로 반영한다.

## 저장·권한·이관

- Resource의 `details`, `files`는 선택 확장이다. 기존 본문형 자료와 워크플로 JSON 버전, 실행 manifest v1을 유지한다.
- 자료와 첨부는 현재 읽기 권한을 서버에서 검사한다. 원본 수정/삭제와 이전 버전 조회/복구는 소유자만 가능하다. 워크플로 공동 편집 권한은 자료 수정 권한을 부여하지 않는다.
- 첨부는 불변 ID와 SHA-256으로 관리한다. 파일 수정은 새 파일로 업로드하며, 자료 저장이 채택한다. 동시 저장에서 하나의 임시 파일을 다른 자료 두 개가 채택하지 못한다.
- 복구는 이전 본문·설정·첨부를 새 버전으로 저장하며 현재 공유 범위를 유지한다. 과거 버전에 없던 확장 설정/파일도 정확히 제거한다.
- 공유 사본은 새 소유자의 파일 ID를 만들고 원본의 불변 바이트를 참조한다. 이후 원본 공유 철회가 이미 합법적으로 만든 개인 사본이나 오프라인 ZIP을 회수하지 않는다.
- 운영 파일 바이트는 `BUCKET` R2 바인딩에 저장한다. 미설정이면 업로드/첨부 내보내기를 미설정으로 표시한다. D1 조각 어댑터는 명시적 개발/테스트 환경에서만 허용한다.
- `0004_resource_packages.sql`은 기존 행을 삭제하지 않고 컬럼·테이블·색인을 추가한다. 로컬 D1 적용 전 `outputs/resource-migration-backup-20261027/d1`에 백업했다. 적용 후 기존 컬럼 비교: 자료 18개, 워크플로 23개, 발행 버전 0개, 감사 736개, 실행 160개 모두 같은 내용. 증거: `outputs/resource-migration-preservation.json`.
- 임시 업로드/이전 첨부는 복구를 위해 보존한다. 운영 보존 기간과 미연결 파일 정리 작업은 자동 제공하지 않는다. 공유 사본이 같은 바이트를 참조하므로 단순 원본 삭제로 R2 객체를 제거하면 안 된다.

## 용량

정본은 `domain/resource-contract.ts`다. 본문 200,000 UTF-16 코드 단위, 유형별 metadata 1,300,000 UTF-8 바이트, studio 요청 전체 4,000,000바이트, 파일당 5,000,000바이트, 자료당 파일 40개/20,000,000바이트, 한 ZIP 전체 첨부 합계 20,000,000바이트다. manifest 텍스트 합계는 기존 8,000,000바이트 제한을 유지한다. 업로드 바이트와 본문 글자 수를 같은 숫자로 표시하지 않는다.

## 사용자·운영 설정

- 웹: 기존 SSO/세션·D1 설정. 첨부 사용 시 `wrangler.jsonc` 운영 설정에 `r2_buckets`의 binding=`BUCKET` 및 실제 bucket_name을 등록하고 원격 D1 마이그레이션을 배포 절차에 적용한다. 이번 작업에서 원격 DB나 R2를 생성/변경하지 않는다.
- 테스트: 별도 테스트 환경에서 `FLOWLY_ENV=development`, `FLOWLY_AUTH_MODE=test`, `FLOWLY_FILE_STORAGE=d1-test`, 로컬 origin과 임의 테스트 세션 비밀을 사용한다. 운영에서 테스트 인증/D1 첨부 어댑터를 활성화하지 않는다.
- 내려받은 폴더: `START_HERE.md`, `.env.example`, `mcp-connections.example.json` 및 선택 기능의 requirements 안내를 따른다. 실제 OpenAI 키·모델·MCP 주소/토큰은 사용자가 해당 로컬 환경에 등록한다. 웹·Git·ZIP에 실제 키를 넣지 않는다.
- Skill 의존성은 로컬에서 별도로 설치한다. Python은 패키지명 또는 `name==version`, JavaScript는 Node 기본 모듈과 동봉 파일을 지원한다. 선언된 패키지만으로 설치 성공을 보장하지 않는다.

## 검증 기록

명령은 PowerShell에서 실행했다. 아래 HTTP origin은 별도 테스트 서버이며 사용자 DB와 분리했다. 전체 예제 증거 갱신은 진행 중이고, 완료한 결과만 별도로 확정한다.

- `pnpm typecheck`, `pnpm lint`, `pnpm build`: 통과. 빌드는 기존 서버의 Windows 파일 잠금을 해제한 뒤 Vinext/Workers 경로로 수행했다. 최종 UI 보강 후 빌드도 통과했고 5173 서버를 다시 시작했다.
- `pnpm test`: 816개, 814 통과, 실패 0, 건너뜀 2. 건너뛴 두 검사는 RPA용 Playwright Chromium 미설정이다. 로그: `outputs/resource-integration-unit-final.log`. 새 실제 ZIP 실행 37개와 기존 RAG 39개는 이 전체 검사에도 포함된다. [실행기 검증](RESOURCE_RUNTIME_VERIFICATION.md).
- 실제 HTTP: `FLOWLY_TEST_ORIGIN=http://127.0.0.1:5190 pnpm test:integration` 22시나리오 통과, `tests/workflow-sharing-integration.ts` 7시나리오 통과. 소유자/조회자/편집자/무권한·공유 철회·삭제/권한관리 제한·예제 사본·동시 저장·웹 실제 실행 차단을 확인했다.
- `tests/resource-http-integration.ts`: D1 테스트 첨부 어댑터에서 5검사그룹, 로컬 Miniflare R2 바인딩에서 같은 5검사그룹 모두 통과. 실제 API로 업로드·다운로드하고 받은 Node/Python Agent ZIP을 풀어 CLI를 실행했다. 소유/조회/무권한, 공유 사본, 버전·CAS·복구·철회, 조회자의 충돌 응답에 공유 이메일 숨김을 확인했다. 원격 R2 검증은 아니다. 로그: `outputs/resource-http-test-final.log`, `outputs/resource-http-r2-test-final.log`.
- `python scripts/audit-python-tool-support.py --check`: 195/195 소스/공개 계약 대조 일치. 알고리즘 195개 실행 검증을 의미하지 않는다.
- 브라우저: 별도 5190 DB에서 수행한 결과와 스크린샷은 [UI 검증](qa/RESOURCE_EXPERIENCE_UI.md)에 기록한다. Chrome 확장의 로컬 파일 접근 제한 때문에 네이티브 파일 선택 후 업로드 조작 전체는 미검증이며, API로 실제 업로드한 파일의 편집·초안 보호를 검증했다.
- 외부 OpenAI·MCP 서비스 호출: 없음. 모델·MCP 경계만 명시적인 테스트 대역을 사용한다.

## 검증 범위의 한계

- 실제 SSO/원격 R2/사내 MCP/OpenAI 계정, 실제 모델 품질, 실제 Cowork/Codex 자동 인식은 별도 운영 검증이다.
- 모든 고급 JSON을 일반 입력 폼으로 바꾸지는 않았다. 초안 보존·명시 적용/되돌리기·오류 안내를 제공한다.
- 중첩 오류는 실제 블록 경로와 메시지 기반 탭/관련 입력으로 이동한다. 모든 검증 오류가 고유 필드 ID를 갖는 것은 아니다.
- 등록·구조 검사·사용자 보고 기록·실제 로컬 실행 검증을 구분한다. 웹에서 읽을 수 있다는 이유로 실행 준비 완료를 표시하지 않는다.
