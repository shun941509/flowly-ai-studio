## 브라우저 확인

[UI 검증 상세와 화면](qa/INTEGRATED_EDITOR_UX.md)에 근거를 보관했다.

- 도움말을 닫아도 편집한 이름과 설계 보존.
- 적용 전 하위 초안 저장→다시 열기→복구→상위 반영.
- 중첩 가이드에서 Escape를 누르면 가이드만 닫히고 부모 편집기는 유지.
- 서비스 미설정 대표 예제 복제→다섯 단계 맞춤 설정→실제 하위 Agent 지침 반영→저장→새로고침 유지.
- 정확한 ID로 만든 QA 사본만 정리했으며 기존 사용자 워크플로·자료는 보존.

## 검증 중 발견하여 수정한 문제

- 발행·복원 충돌 응답에서 비소유자에게 공유 이메일 목록을 반환하던 부분을 정리했다.
- 웹 JSON에는 설계 필드만 내보내고 ACL 메타데이터를 제거했다.
- ZIP 생성 전후에 현재 워크플로·자료 권한을 검사한다.
- RAG 평가 자료 ID도 본문 검색 자료와 함께 재연결한다.
- 로컬 MCP 변수 역할이 모델 비밀 항목과 충돌하는 것을 환경 파일 읽기 전에 차단한다.
- 미설정 새 실행·재개는 작업을 대기열에 넣지 않고 필요한 설정을 안내한다.
- 같은 환경 파일을 공유하는 다른 프로필의 대기·실행 작업과 잠금도 설정 변경을 차단한다.
- 중지는 배정 중인 작업, 최근 목록 200개 밖의 활성 작업, 늦게 시작된 작업에도 취소를 전달한다.
- 자동 새로고침이 사용자가 선택한 과거 실행이나 프로필을 되돌리지 않는다.
- 중첩 모달 Escape가 부모 편집기를 닫는 문제를 실제 화면에서 수정·재확인했다.

전체 예제 검증의 400개 항목 처리 사례는 4개 동시 검사에서 검사기 60초 제한을 넘겼다. 다른 작업을 마친 뒤 1개 작업과 검사기 120초 제한으로 다시 실행하여 Node.js·Python의 8개 시나리오가 모두 통과했다. 제품의 실행 한도·시나리오·단언은 바꾸지 않았고, 기존 226개 증거는 현재 지문·설계·두 ZIP 해시를 확인한 후 재사용했다. 최종 `examples/workflow-verification.json`은 227개 전체와 0개 실패를 포함하며 타입 검사에서 227/227개의 현재 검증 표시를 재생성했다.

초기 전체 테스트의 시간 측정 두 항목은 CPU 부하에 민감했다. 상위 예산 검사는 가상 시계로 정확한 남은 시간을 확인하고, 병렬 검사는 제한된 경계 대기로 실제 겹침을 검사하도록 바꿨다. 제품 실행 한도나 동시성 단언을 완화하지 않았다. Windows Python 기본 인코딩의 초기 검사 오류는 UTF-8 환경으로 재실행하여 해결했다.

빌드 중 실행 중인 Worker의 폴더 잠금과 한 차례 Node 종료 단계 오류가 있었다. 대상 로컬 서버를 종료하고 같은 빌드 경로를 다시 실행하여 정상 종료를 확인했다. 사용자 데이터베이스는 초기 추가 마이그레이션 전에 백업했다.

## 미검증·사용자 설정

- 실제 회사 SSO 왕복·운영 배포·실제 모델 답변 품질·사내 MCP의 외부 효과는 미검증이다.
- 사용자가 내려받은 환경에서 런타임/선택 의존성을 준비하고 `.env` 또는 로컬 설정 화면에 모델·MCP 값을 등록해야 한다.
- Cowork·Codex 자체에서 실제 AI에게 작업을 맡기는 검증은 수행하지 않았다. 제공하는 파일·지시문·수정본 계약과 실제 로컬 실행기를 검증했다.
- 임의 외부 코드 수정의 의미를 자동으로 노드 그래프에 역변환하지 않는다. 코드 변경은 별도 표시하고 검토해야 한다.
- 이미 내려받은 자료는 원격 공유 철회로 회수하지 못한다. 초안은 해당 사용자·탭 범위로 복구하며 실시간 공동 커서 편집을 추가한 것은 아니다.
