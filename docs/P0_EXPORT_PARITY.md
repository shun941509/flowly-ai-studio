# 99개 기획 구현의 P0 — 실행기 기본값과 내보내기 일치

작업일: 2026-10-24 (Asia/Seoul)

## 범위

이번 P0는 기존 앱 실행 기반을 만들었던 과거 P0와 구별한다. [99개 대응표](EXAMPLE_99_IMPLEMENTATION_MAP.md)를 기준으로 현재 소스를 재사용하며 두 내보내기 경로와 실행기의 일치부터 보강한다. 99개 전체를 구현 완료한 단계가 아니다.

- 웹은 설계·자료 관리·미리보기·내보내기를 담당한다. 웹의 신규 live 요청과 이전 live 대기열은 실행 전에 차단한다.
- 실제 실행은 사용자가 내려받은 Node.js/Python 프로젝트에서 수행한다. 이번 검증에는 실제 모델·사내 MCP 서비스나 자격 증명을 사용하지 않는다.
- 기존 JSON v1~v5, 편집기, 자료 권한, 승인·재개, Vinext/Workers/D1, pnpm을 유지한다. 회사 네트워크를 대신하는 주소 허용 목록은 추가하지 않는다.

## 변경 계약

### 작업 조정 기본값

적응형 작업 조정의 `maxRounds` 생략 시 기본값을 두 언어와 편집기에서 **3**으로 맞춘다. Node.js는 기존에 1, Python·편집기는 3이었다. 명시된 값은 그대로 사용하고, 단일 계획 방식은 기존 동작을 유지한다. 이는 최대 재계획 횟수이며 반드시 세 번 실행한다는 뜻이 아니다. 완료 응답·실행 예산·오류가 먼저 도달하면 중단한다.

JSON에 생략된 필드를 강제로 채워 저장하거나 스키마 버전을 변경하지 않는다. 새로 내보내는 실행기부터 같은 기본값을 적용한다. 이미 내려받은 ZIP의 실행 코드를 자동으로 바꾸지 않으므로 사용자는 재내보내기해야 한다.

### 모델 설정의 빈 값·공백 처리

Python의 모델명 앞뒤 공백을 Node.js와 동일하게 제거하고, 임베딩 모델명이 생략되거나 빈 값/공백이면 양쪽 모두 `text-embedding-3-small`을 사용한다. 요청에 사용하는 이름, 최초 실행에 고정한 이름, 승인·검토 후 재개 시 비교하는 이름을 일치시킨다. 모델 키나 필수 응답 모델명 자체가 없으면 계속 미설정으로 중단한다. 이 변경은 새로운 모델 API 호출을 추가하지 않는다.

### 동일한 내보내기 구성

편집기와 예제 직접 다운로드가 공통 패키지 구성을 사용한다. 예제 경로에서 빠졌던 다음 파일을 동일한 조건으로 포함한다. 파일/자동 시작 도우미는 해당 노드가 있을 때 포함하고, 운영 도우미는 두 경로 모두 포함한다.

- `flowly_files.py`, `requirements-files.txt`: 파일 처리와 필요한 의존성 안내
- `flowly_triggers.py`: 사용자가 시작하는 자동 실행 도우미
- `flowly_ops.py`, `flowly_local.py`, `OPERATIONS.md`: 로컬 운영·검토·승인·재개·백업 안내

언어별 `runner.mjs` 또는 `runner.py`, `workflow.json`, `.env.example`, `README.md`, `.gitignore`는 유지한다. 예제 ZIP에는 기존 입력 예시·예제 계약·설명도 유지한다. 키와 테스트 응답은 포함하지 않는다.

새 공통 패키지 모듈도 검증 지문에 포함한다. 실행기나 패키지 구성 변경 시 이전 ZIP의 검증 배지를 그대로 재사용하지 않으며, 실제 ZIP을 다시 생성·실행한 기록으로 갱신한다.

`AI_PROMPT.md`, `AGENTS.md`, `START_HERE.md`, `skills/*/SKILL.md`의 AI 작업 지침 묶음은 **P1 신규 개발**이다. 이번 필수 실행 파일 누락 수정과 구별한다.

### 회귀 검사에서 드러난 로컬 HTTP 경계

확장 회귀 중 Windows에서 로컬 운영 화면·자동 시작 서버가 작은 잘못된 요청을 거절할 때 `WinError 10053`을 재현했다. 오류 응답을 먼저 전송하고 송신 방향을 종료한 뒤, 남은 수신을 최대 **64KiB·100ms**만 폐기하도록 보강했다. 인증/출처/경로/크기 검사는 그대로 적용한다. 지연된 작은 본문의 403/404/415/413 응답, 거절 후 명령 실행 0회, 본문 없는 과대 요청 뒤 후속 정상 요청을 검사했다. 연결 오류를 무조건 허용하는 방식으로 검사를 약화하지 않았다.

## 검증 기준

1. 생략된 반복 횟수·명시된 값·중첩 흐름·종료/한도 경계를 실제 두 CLI에서 비교한다. 모델명의 공백과 임베딩 모델명의 생략/빈 값/공백/명시값을 검사하고, 검토 후 재개에서 이미 완료한 모델·검색 호출을 반복하지 않는지 확인한다.
2. 예제와 편집기 패키지의 공통 파일을 비교하고 파일/자동 시작 노드를 실제 로컬 프로세스로 실행한다.
3. 기존 102개 설계의 정상·경계 시나리오를 두 언어 ZIP으로 다시 실행한다. 모델·임베딩·MCP 응답은 ZIP 밖 테스트 경계에서만 주입하며 다른 네트워크와 부모 자격 증명 전달은 차단한다.
4. 실제 웹 API 처리 함수와 대기열 처리 함수가 live 요청을 차단하는지 검사한다. 인증·저장소만 테스트 대역을 사용하고, 실행기 호출이나 네트워크 요청이 발생하면 실패시킨다.
5. 타입 검사·린트·Vinext/Workers 빌드와 관련 기존 회귀 검사를 수행한다.

실행 결과는 이 문서의 아래 기록을 따른다. 과거 `EXAMPLE_VALIDATION.md`의 숫자를 이번에 새로 실행한 결과로 사용하지 않는다. 3,200개 목표용 `catalog:complete`는 99개 기획의 완료 판정이 아니다.

## 사용자 설정 위치

1. 웹의 **도구 및 자료 → MCP**에서 사내 연결 주소, 도구 정의, 연결 ID, 주소/토큰 환경 변수 이름을 등록한다. 토큰 원문을 등록하지 않는다.
2. ZIP을 푼 실행 폴더에서 `.env.example`을 `.env`로 복사한다. `OPENAI_API_KEY`, `FLOWLY_MODEL`, 해당 ZIP README에 적힌 `FLOWLY_MCP_ENDPOINT_…`, `FLOWLY_MCP_TOKEN_…`를 사용자가 로컬 편집기에서 설정한다.
3. Node.js는 `node runner.mjs check`, Python은 `python runner.py check`로 준비 상태를 확인한다. 설정 누락은 `unconfigured`로 표시하고 가짜 성공 결과를 만들지 않는다. `check`는 실제 연결 검사가 아니다.
4. 파일 처리·자동 시작·운영 도우미를 사용하는 Node.js 프로젝트도 Python이 필요하다. Python 실행 파일 선택과 파일/OCR 추가 의존성은 ZIP README를 따른다.

실제 모델 답변 품질, 사내 서비스 계약과의 호환성, 운영 SSO 왕복·배포는 이번 검증에 포함하지 않는다. 내보낸 자료는 오프라인 사본이므로 원본의 이후 공유 철회를 원격 재검사하지 않는다.
