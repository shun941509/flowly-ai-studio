# Flowly 통합 기능 명세

예제 카탈로그와 프레임워크 내보내기를 포함한 상위 통합 명세는 [EXAMPLE_PLATFORM_SPEC.md](EXAMPLE_PLATFORM_SPEC.md)다. 이 파일은 현재 31종 노드와 실행 설정의 상세 구현 기준을 관리한다.

갱신: 2026-10-24 · 그래프 v5. 2026-10-22의 제안 32개·추가 노드 7종 명세를 보존하고, 후속 P1~P4 변경을 별도 표로 추가했다. `구현됨`은 명시한 범위의 소스가 있다는 뜻이며 실계정 모델·SSO·운영 배포 검증을 뜻하지 않는다. 검증 명령과 결과는 [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)에 별도로 기록한다. 카탈로그 114개와 기획 99개는 다른 목록이며 99개 전체와 P2~P4 모든 확장 기능은 미완료다.

## 제품과 실행 경계

한국어 웹은 설계·자료 관리·공유·발행·내보내기만 담당하며 **OpenAI를 호출하거나 API 키를 받지 않는다.** Node.js와 Python ZIP은 사용자가 내려받은 환경에서 실제 모델과 허용 도구를 실행한다. 모의 제공자는 개발 테스트에서만 주입한다. 설정이 없으면 미설정으로 중단하며 가짜 답변을 성공으로 표시하지 않는다.

- 실행기의 키는 명시한 로컬 `.env`에서만 읽는다. 셸의 기존 키를 대신 사용하지 않는다. 내보낸 ZIP·JSON·로그에는 비밀 값을 넣지 않는다.
- 모델이 필요 없는 흐름은 키 없이 실제 데이터·파일 처리를 수행한다. 벡터 검색에는 임베딩 키, 웹 검색·모델 평가·분류·Agent에는 Responses 모델 설정이 필요하다.
- 서버는 검증한 세션으로 원본 소유권·현재 자료 권한·본인 서비스 연결을 확인한다. 새 발행본 내보내기도 현재 자료 권한을 다시 검사한다.
- **이미 내려받은 자료는 독립 복사본이다. 원본의 공유 철회나 삭제가 복사본을 원격 회수하지 못한다.** 발행 버전은 워크플로 정의의 고정본이고, 자료는 내보내는 시점에 접근 가능한 내용을 복사한다.
- 실행 기록·체크포인트·승인·검토·보완 입력 요청·사용량은 지속 저장한다. 쓰기 결과가 불명확하면 자동 재시도하지 않는다. 내부 사고 원문은 저장하지 않는다.
- 외부 그래프는 DAG, 하위 정의는 최대 깊이 3·전체 120노드, 명시적 병렬 작업은 최대 동시 4개다. 일반 DAG의 모든 갈래를 자동 병렬화하지 않는다.

팔레트는 총 **31종**이다. Agent와 에이전트는 같은 노드이며 별도로 중복하지 않는다. 멀티 에이전트는 에이전트 팀, 오케스트레이션은 작업 조정 노드로 제공한다.

| 구분 | 노드 |
| --- | --- |
| 입력·자료 | 사용자 입력, 입력 양식, 자동 시작, 파일 입력, 자료 가져오기, 작업 지침 |
| AI·검색 | AI 답변, Agent, AI 분류, 문서 검색 |
| 조정·흐름 | 조건, 병렬 작업, 에이전트 팀, 작업 조정, 하위 워크플로, 반복 처리, 결과 모으기 |
| 처리·검증 | 도구 실행, 값 변환, 계산·검증 프로그램, 문서 내용 추출, 민감정보 필터, 답변 평가, 사람 검토, 오류 처리, 기억 읽기·쓰기, 보상 작업 |
| 결과 | 답변 출력, 파일 출력 |

| 기능 | 제공 위치 | 이유와 동작 |
| --- | --- | --- |
| PDF·Word·Excel·텍스트 추출 / 표 / OCR | 문서 내용 추출의 방식 | 같은 파일 계약과 출처를 사용. OCR은 로컬 엔진·언어 데이터가 필요 |
| RAG·벡터·웹 검색 | 문서 검색의 방식 + AI 답변/Agent 연결 | 어휘 검색, 실제 임베딩 기반 로컬 색인, 제공자 웹 검색을 선택. 근거·출처·빈 결과 구분 |
| 적응형 오케스트레이션 | 작업 조정의 계획 방식·최대 라운드 | 완료 결과로 허용 작업만 재선택. 계획·라운드 체크포인트와 전체 한도 적용 |
| 선행 작업·완료 조건 | 작업 조정의 작업별 `dependsOn`·`completion` | 등록한 선행 작업의 산출물을 전달하고 조건으로 완료를 판정. 모델의 완료 선언만으로 성공하지 않음 |
| 실행 중 보완 입력 | 입력 양식의 `request` 방식 | 지속 입력 요청·기한·필드 검증 후 같은 실행을 명시적으로 재개. 생략 시 기존 시작 입력 방식 보존 |
| 원격 기억·보관 기간 | 기억 읽기·쓰기의 저장 위치·TTL | 로컬 또는 MCP 계약. 사용자·워크플로 범위 강제, 외부 변경 승인 |
| 파일 양식 | 입력 양식의 파일 필드 | 내보낸 프로젝트 inputs/ 아래 상대경로만 허용 |
| 스트리밍 | 답변 출력의 설정 | Responses 부분 이벤트와 최종 완료·사용량을 구별. stderr JSONL 및 지속 이벤트 |
| 한도·입출력 매핑·스키마·오류 경로 | 각 노드 설정 | 실행 절차의 공통 정책이므로 별도 노드로 중복하지 않음 |
| 도구 결과 확인 후 답변 완료 | Agent의 Harness 설정 | `requireToolResult`를 켜면 현재 Agent가 허용된 도구를 성공적으로 호출한 결과가 있어야 완료. 미호출 답변은 기존 한도 안에서 재판단하며 다른 Agent·실패 도구 호출로 대체 불가 |
| 버전·프로필·큐·평가 사례·백업·감사 | 워크스페이스 또는 로컬 운영 화면 | 하나의 흐름을 관리하는 기능이며 캔버스 노드가 아님 |

## P1~P4 후속 구현 범위

| 단계 | 기능과 제공 위치 | 구현 계약과 제한 |
| --- | --- | --- |
| P1 | 입력 양식·CLI·로컬 운영의 보완 입력 | `form.mode=request`이면 `waiting_input`으로 지속 저장. `submit`은 유효한 값만 저장하고 `resume`에서 진행. 중첩 상위 대기와 완료한 다른 작업을 보존하며 만료·소유자·설정/입력 해시·출력 스키마 검사 |
| P1 | AI 작업 문서 내보내기 | 두 ZIP에 START_HERE·AI_PROMPT·AGENTS·WORKFLOW_GUIDE와 workflow/선택 Skill의 SKILL.md 포함. 동일 manifest의 매핑·분기·의존 관계·허용 도구·한도 사용. 전역 설치·비밀 값 복사·AI 도구 자동 인식 보장 없음 |
| P2 | 새 `program` 노드 | 등록된 여섯 결정적 계산·검사만 실행. 공통 출력은 `{text:정규화한 결과 JSON,data:결과}`. Node 번들 및 Python의 조건부 `flowly_programs.py`로 같은 계약 제공. 네트워크·임의 코드·SQL 실행 없음 |
| P3 | 작업 조정 계약 | `tasks[].dependsOn`은 등록한 선행 ID만 허용. 정의·입력 해시와 완료 결과를 기록하며 필요한 선행 산출물만 전달. `completion`은 `{input,artifacts}`를 검사. 동일 계약의 완료 작업 재사용과 불명확 쓰기 중단. 동적 역할 생성은 후속 dynamic 방식으로 제공한다. 분산 점유·일반 업무 종속 결과 무효화는 미구현 |
| P4 | 대표 기술 팀·DB 변경 흐름 | 기술 근거→등록 구현 작업→시험→독립 검토→승인된 적용→DB 변경·검증·별도 승인 복구. 시험/검토 실패는 변경을 차단. 제품에는 사내 MCP 계약만 포함하며 범용 샌드박스·DB 서버를 내장하지 않음 |

| 등록 프로그램 | 기능 | 완료로 판단하지 않는 범위 |
| --- | --- | --- |
| `numeric_summary` | 같은 단위 숫자의 개수·합·최소·최대·평균 | 통화용 임의 정밀도 계산·단위 변환 |
| `schema_check` | 기존 Flowly 스키마 검사와 오류 경로 | 임의 JSON Schema 확장 |
| `schema_patch` | 현재 오류인 정확한 경로만 수정한 후 전체 재검사 | 정상 필드 변경·자동 삭제·루트 전체 교체 |
| `evidence_check` | 출처 ID·버전·비어 있지 않은 정확한 인용 대조 | 인용 내용의 의미·사실성 보장 |
| `goal_check` | 명시한 조건을 실제 값에 평가 | 빠진 값이나 빈 조건을 성공 처리 |
| `rank_fusion` | 여러 검색 순위의 중복 통합·재정렬·출처 보존 | 검색/임베딩 자체 실행·빈 근거 생성 |

계약·한도는 [프로그램 명세](P2_PROGRAMS.md), 문서 구성은 [AI 내보내기](P1_AI_EXPORTS.md), 실제 서비스와 테스트 경계의 구분 및 남은 범위는 [P1~P4 구현 기록](P1_P4_IMPLEMENTATION.md)과 [범위 검토](P1_P4_SCOPE_REVIEW.md)를 따른다. 노드가 존재한다는 이유만으로 기획 예제 전체를 구현 완료로 분류하지 않는다.

## 동적 Agent·지식 색인·후보 탐색 후속 계약

| 제공 위치 | 구현 | 명시적인 제한 |
| --- | --- | --- |
| 작업 조정 `mode=dynamic` | 생성 작업 입력 스키마·기능 틀·의존 DAG, 생성 수/병렬 수, 계획 해시·부모 예산·동일 ID 재개 | 새 도구/코드/권한 생성 금지. 동적 노드를 포함한 전체 그래프의 보수적 최대 전개 블록 120개 |
| `knowledge` | 준비·평가·발행·검색·철회·복구·상태, 변경 청크 임베딩 재사용, 리비전 CAS | 로컬 색인. 최대8세대·세대당100조각·변경128건·상태200,000자. 현재 발행 세대만 검색, 검색 방식/모델 일치 검사 |
| `candidate_search` | ToT frontier·가지치기·되돌림 / GoT 다중 부모·수정·자손 무효화, 지속 상태 | 양의 정수 합계 문제의 등록 검증기. 후보 최대64·깊이8·반복32 설정에 전체 실행 예산도 적용. 일반 업무 의미 검증은 별도 |

두 ZIP과 AI 작업 문서는 같은 실행 정의를 사용한다. Python 도우미는 필요한 기능만 포함하며 누락 시 중단한다. 실제 서비스 없이 수행한 실행 검증과 남은 범위는 [후속 구현 기록](DYNAMIC_RAG_SEARCH_IMPLEMENTATION.md)을 따른다.

## 32개 제안의 우선순위와 상태

초기 분류는 A 단계 명세의 분류를 보존한다. 현재 범위에서 미구현 항목을 완료로 간주하지 않도록 운영상의 제한을 마지막 열에 명시했다.

| ID | 기능 | 초기 분류 / 우선순위 | 현재 상태와 지원 범위 |
| --- | --- | --- | --- |
| N01 | 직접 MCP 도구 실행 | 구현됨 / A | 구현됨. 지정 도구 1개, 고정 인자와 앞 단계 값, 도구 스키마·허용 목록·승인·중복 방지 |
| N02 | 값 변환 | 구현됨 / A | 구현됨. 필드 선택·문자열 양식·JSON 읽기, 임의 업로드 코드 실행 없음 |
| N03 | 결과 모으기 | 구현됨 / A | 구현됨. 활성 경로만 객체·배열·문자로 결합·중복 제거 |
| N04 | 문서 검색/RAG | 보강 필요 / A→B | 구현됨. 어휘·벡터·웹 검색, 자료 버전·조각·근거 URL. 벡터는 사용자·워크플로·자료·모델별 로컬 색인. 외부 벡터 DB 제품 어댑터는 제공 범위 밖 |
| N05 | 사람 검토·수정 | 구현됨 / B | 구현됨. 지속 검토·수락·수정·거절·재개. 검토와 외부 쓰기 승인 별개 |
| N06 | 오류 경로 | 구현됨 / B | 구현됨. 일반 오류의 success/error 경로·대체 안내·사람 검토 연결. 권한·필터 차단·취소·한도·불명확 쓰기는 우회 불가 |
| N07 | foreach/batch | 구현됨 / B | 구현됨. 최대 20항목·동시 4개·항목별 체크포인트와 부모 예산. 초과 항목을 조용히 자르지 않음 |
| N08 | AI 분류/라우팅 | 구현됨 / B | 구현됨. 허용한 2~8라벨 중 하나를 선택하고 해당 경로만 실행 |
| N09 | 구조화 입력·파일 | 보강 필요 / B | 구현됨. 글·숫자·불리언·날짜·선택·파일 상대경로, 필수값·미등록 필드 검증. 시작 입력과 실행 중 보완 입력을 구분. 파일은 사용자 로컬 inputs/에서 읽음 |
| N10 | 메모리 읽기/쓰기 | 보강 필요 / C | 구현됨. 로컬/MCP 읽기·쓰기·삭제·TTL. 원격 도구는 namespace/key/action/value/expiresAt 계약을 지원해야 함 |
| F01 | 실제 병렬 실행 | 구현됨 / B | 구현됨. 작업별 실제 동시 실행·고정 결과 순서·예산 분배·취소·저장 직렬화 |

## 새 실행 계약과 안전 경계

노드 상세 설정은 [NODE_V5_CONTRACT.md](NODE_V5_CONTRACT.md), 기존 중첩 실행은 [NODE_V4_CONTRACT.md](NODE_V4_CONTRACT.md), 로컬 운영 요청은 [OPERATIONS.md](../export-runtime/OPERATIONS.md)를 따른다.

- v1→v2→v3→v4→v5 명시 변환으로 기존 JSON을 읽으며 기존 명시 매핑과 스키마를 보존한다. 알려지지 않은 설정·미래 버전은 거절한다.
- 파일 처리 Node 실행기는 공용 Python 도우미를 사용한다. 기본 데이터/Agent Node 실행에는 Python이 필요 없지만 파일·운영·트리거 도우미는 Python 3.11 이상이 필요하다.
- 파일 라이브러리·OCR 엔진·언어 데이터는 ZIP에 숨겨 설치하지 않는다. `check`에서 미설정을 표시하며 사용자가 안내대로 설치한다. 경로 이탈·심볼릭 링크/정션·압축 팽창·변경된 입력 해시·기존 출력 덮어쓰기를 막는다.
- 트리거는 127.0.0.1에서만 수신한다. HMAC·타임스탬프·이벤트 ID·본문 해시와 영속 영수증으로 인증·중복을 검사한다. 알 수 없는 실행 결과를 재시도하여 외부 쓰기를 중복시키지 않는다.
- 로컬 화면은 정확한 Host/Origin·임시 접근 토큰·CSP를 검사한다. 임의 셸 명령을 제공하지 않는다. 실행기는 명시 환경 파일만 읽고 자격 증명이 있는 부모 환경을 상속하지 않는다.
- 원격 서비스와 모델의 권한·동작·품질은 실계정으로 검증해야 한다. 구현과 모의 HTTP 테스트가 실제 제공자 성공을 뜻하지 않는다.

## 검증 근거와 남은 설정

2026-10-22 v5 단계에서는 실제로 내려받은 양쪽 실행기로 파일·OCR·예약·큐·평가·백업/복원을 실행했다. 모델/임베딩/웹 검색/원격 기억/보상은 모의 제공자·HTTP 계약·승인·오류 테스트와 미설정 차단을 검사했다. **당시 실제 OpenAI·MCP·외부 쓰기 호출은 0회였다.** 공식 문서·개발용 패키지·OCR 언어 데이터 다운로드는 실행 API 호출과 구별한다.

2026-10-24 P1~P4 단계도 실제 외부 OpenAI·MCP 호출은 0회다. 실제 ZIP의 입력 대기·재개, 등록 프로그램, 의존 작업과 완료 조건, 테스트 경계의 고정 Python 시험·SQLite 변경/복구를 검증 대상으로 삼았다. 새 최종 통합 검사 수는 [단계별 기록](P1_P4_IMPLEMENTATION.md)에 확정 후 기입하며 과거 v5 통과 수를 승계하지 않는다.

남은 설정은 사용자의 로컬 모델 키/모델명, 필요 서비스 토큰과 실제 MCP 계약, OCR 선택 시 라이브러리·Tesseract·언어 데이터, 웹 운영 시 OIDC·D1·인증 비밀·배포 정책이다. 기존 키를 조회·복사·등록하거나 운영 배포하지 않았다. 제공 범위 밖인 무제한 실행·임의 업로드 코드·원격 복사본 회수·외부 서비스 원자적 rollback을 완료 기능으로 표시하지 않는다.
