# 남은 84개 기획 통합 구현 기록

기준일: 2026-10-25. 이전 분류의 보강 필요 57개·신규 개발 21개·후순위 6개를 하나의 작업으로 다룬다. 기획 100개와 전체 소스 카탈로그는 다른 집합이다. 이전 16개 구현 기획을 보존하고 나머지 84개에 독립적인 Agent 워크플로를 대응한다.

## 원래 요구와 실행 계약

[100개 수용 명세](EXAMPLE_100_ACCEPTANCE_SPEC.md)는 원래 요구·실제 수용조건·담당 소스·사용자 설정을 함께 기록한다. [100개 현재 대응표](EXAMPLE_100_IMPLEMENTATION_MAP.md)의 구현 상태는 로컬 실행 계약의 범위다. 외부 모델의 정답률이나 회사 시스템 접속 성공을 의미하지 않는다.

| 범위 | 구현 방식 |
| --- | --- |
| 조사·근거·업무 복구 23개 | 참조에 근거한 후속 조회, 규정 적용·변경, 문서 반입, 페이지와 항목 반복, 독립 후보 평가, 실제 예산, 조회 신뢰, 표 대조, 서비스 영수증, 프로젝트 교훈과 반례 회귀 |
| 기술·협업·지식 32개 | 제약·민감도·변경 영향 계산, 충분한 병렬 결과 조기 선택, 충돌·CAS·작업 점유, 시점·권한·수치 RAG, 절차·API·코드 계약, 목적별 아바타 상태 전이 |
| 코드·DB·통합 29개 | 등록 코드의 실제 분리 프로세스 시험, 차등·변이 검사, 실제 로컬 브라우저 입력, SQLite 변경·백업·복구, 지식 수명주기, 목표 의존 무효화, 공유 작업판, 전체 블록의 분기·복구 |

노드 이름·프롬프트·좌표를 제외한 구조와 실행 계약을 정규화해 중복을 거절한다. 각 예제는 명시적 Agent와 정상·경계 시나리오를 갖는다. 기존 사용자 문서와 예제 소스는 유지한다.

기획 100개는 기존 구현 16개와 이번 84개로 대응한다. 전체 소스 그래프는 227개이며 그중 명시적 Agent 예제가 156개, 기존 보조 흐름이 71개다. 이번 추가 수는 84개이며 프레임워크 변형이나 이름만 다른 복사본을 더하지 않는다. 과거의 3,200개 목표까지 완료했다는 뜻은 아니다.

## 공통 실행기 보강

- 등록 프로그램 블록의 `completion` 방식은 고정 `operation`과 JSON `arguments`를 사용한다. 116개 등록 연산 중 선택한 공개 계약은 `completion-manifest.json`, 구현은 ZIP의 고정 Python 모듈이다. Node.js와 Python이 같은 계산 코드를 실행한다. 임의 명령·코드·SQL을 입력받아 실행하는 기능은 제공하지 않는다.
- 코드·DB 프로그램은 격리된 로컬 참조 작업물에서 실제 파일과 프로세스·SQLite를 사용한다. 회사 저장소나 운영 DB에 적용하려면 등록한 사내 MCP 계약과 승인 흐름을 연결한다. 로컬 참조 연산 성공을 회사 시스템 변경 성공으로 기록하지 않는다.
- 병렬 완료 정책 `first_match`는 하위 흐름의 최종 출력에 고정 조건을 적용한다. 먼저 충족한 결과를 저장하고 미완료 작업을 취소한다. 대기 중 승인·검토를 무효화하며 이미 완료된 작업은 유지한다. 전송된 외부 쓰기의 결과가 불명확하면 성공 대신 `unknown_outcome`으로 멈춘다.
- 예산 계획 프로그램에는 실행기가 실제 사용한 모델 판단·도구 호출·토큰·남은 시간을 주입한다. 입력이 이 값을 위조할 수 없다.
- 공유 작업판의 점유 만료에는 실행기의 현재 시간을 주입한다. 사용자나 모델이 전달한 시각으로 임대를 연장할 수 없으며 저장 버전 충돌은 기존 결과를 덮어쓰지 않는다.
- 프로그램 코드·계약·도구 설정의 지문을 실행 기록에 저장해 변경 후 재개를 거절한다. Windows 격리 Python 프로세스에 `-X utf8`을 명시해 한글·이모지 전달을 보존한다.
- Windows의 긴 상태 경로에서도 원자적 메모리·벡터 저장을 지원한다. 체크포인트 저장 직후 실행 프로세스를 강제 종료한 뒤 같은 실행 ID를 복구하는 검사를 두 ZIP에서 수행했다.
- 아바타 상태와 안내는 저장된 결과의 정적 SVG로 내보내며 로컬 HTML 보고서에서 확인·저장할 수 있다. 임의 SVG를 페이지 본문 코드로 실행하지 않는다. 음성·영상 생성이나 실제 사람의 아바타를 가장하지 않는다.

## 사용자 설정 및 다섯 가지 내보내기

웹에서는 OpenAI를 호출하지 않고 키를 등록받지 않는다. MCP 정의는 **도구 및 자료**에 등록한 사내 연결을 사용한다. 사용자는 ZIP을 풀어 `.env.example`을 `.env`로 복사하고 필요한 `OPENAI_API_KEY`, `FLOWLY_MODEL`, 연결별 MCP 주소·토큰을 직접 입력한다.

Node.js 22 이상과 Python 3.11 이상을 사용한다. Node.js의 Python 경로는 `.env`의 `FLOWLY_PYTHON`에 설정할 수 있다. 선택 프로그램의 의존성은 `requirements-completion.txt`, 기존 도구의 의존성은 `requirements-tools.txt`에 있다. 화면 조작 예제는 명시한 Playwright 버전과 로컬 Chrome이 필요하다. 실행기 `check`가 누락된 의존성을 표시하며 자동 설치하거나 외부 서비스로 대체하지 않는다.

Node.js ZIP·Python ZIP 모두 `AI_PROMPT.md`, `AGENTS.md`, `skills/flowly-workflow/SKILL.md`, `START_HERE.md`, `WORKFLOW_GUIDE.md`를 동일한 `workflow.json`에서 생성한다. AI 문서가 실행기의 상태·권한·승인 계약을 대체하지 않는다. 비밀값과 검증용 모델·MCP 응답은 제품 ZIP에 포함하지 않는다.

## 검증 기록

실제 내보낸 CLI와 계산·파일·저장·승인·재개는 제품 코드를 실행한다. 모델·MCP 응답만 테스트 경계로 제공하며 외부 네트워크 요청은 차단한다. 따라서 이 검사는 실행 계약을 검증하고 실제 모델의 정답률은 평가하지 않는다. 현재 지문에 해당하는 전체 실행 증거는 `examples/workflow-verification.json`을 기준으로 한다.

진행 중 부분 검사와 과거 지문 증거를 최종 완료 수에 합산하지 않는다. 최종 현재 증거는 **227개 그래프·454개 ZIP·2,384개 검사 통과, 실패 0**이다. 이번 84개를 포함해 제목·프롬프트를 제외한 구조 227개와 실행 설정 227개가 구분된다. 이 정규화 검사만으로 업무 의미의 유용성까지 증명한다고 주장하지 않는다.
