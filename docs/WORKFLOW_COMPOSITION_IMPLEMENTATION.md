# 범용 워크플로 조합 P0~P4 통합 구현

> 2026-10-26 현재 통합 계약: [통합 사용자 기능 명세](INTEGRATED_USER_WORKFLOW.md), [최신 검증 결과](INTEGRATED_VERIFICATION.md). 아래 날짜별 기록은 당시 구현·검증 범위입니다. Agent 다운로드의 Agent 필수 조건은 철회되었으며, 워크플로는 별도 읽기·지정 수정 공유를 지원합니다.

이 작업은 사람이 목표를 정하고, 조사·분업·검토·보완·승인·완료하는 방식을 블록으로 조합하는 편집 경험을 보강합니다. 회사 업무만을 위한 고정 템플릿이 아니라 사용자가 직접 만든 설계를 같은 실행 계약으로 내보내는 것이 기준입니다. 기존 React·Vinext·Workers·D1, 자료 권한, DAG, v5 정의와 두 실행기를 유지했습니다. 새 DB 마이그레이션이나 정의 버전 변경은 없습니다.

## 구현 범위

| 단계 | 구현한 내용 | 확인 방법 |
| --- | --- | --- |
| P0: 설계 계약 | 입력 연결과 출력 형식을 기존 스키마 위에서 편집. 직접 선행 노드·필수 입력·자료형 차이 안내. 실제 도구 응답 `data`, 하위 흐름 직접 출력, 병렬·반복 `results.N.output` 경로 구분 | 필드 발견·실제 입력 해석·스키마 검사·잘못된 매핑 테스트 |
| P1: 시각 편집 | 하위 워크플로·병렬 작업·Agent 팀·오케스트레이션 작업·반복 내부를 같은 캔버스로 편집. 상위/하위 경로, 단계별 적용·취소, 연결 즉시 검사, 오류 블록 이동, 선택 정렬·간격, 탭 초안 복구 | 편집 로직·컴포넌트 검사와 실제 브라우저 조작 |
| P2: 실행 의미 | 병렬 전체 대기/조건 충족 종료, 실패 분기, 검토·보완 입력 대기, 목록 반복과 수정 반복의 차이를 설정 화면에서 설명. 기존 실행기의 입출력·대기·재개·완료 조건을 새 조합으로 검사 | 6개 새 설계의 13개 정상·경계 시나리오 |
| P3: 예제 재사용 | 실제 중첩 블록을 분석한 ‘일하는 방식’ 필터·배지. 예제 상세에 목표·입력·Agent 역할·도구·완료 조건 변경 안내 | 필터·페이지 나누기·제목과 무관한 구조 분류 검사 |
| P4: 같은 설계 내보내기 | AI 명령 프롬프트, AGENTS.md, Agent.md, Skill, 일반 실행기와 Agent 진입점의 설계·문서·명령 통일. 긴 프롬프트 무손실 분할 복사. 로컬 운영/트리거 도우미도 Agent 진입점 유지 | 실제 ZIP의 네 실행 경로, 승인·재개·자산 변경 거절, 문서/설계 일치 검사 |

P0~P4는 파일 책임을 나누어 병렬 구현하고 공통 정의와 최종 실행 검증으로 통합했습니다. 새 사용자 조합 검증용 설계는 공개 예제 개수에 추가하지 않았습니다. 기존 예제의 제목·프롬프트를 바꿔 새 프로젝트로 세지 않습니다.

## 편집기에서 사용하는 방법

1. 병렬·Agent 팀·작업 조정·하위 흐름·반복 블록을 선택하고 내부 작업의 **화면에서 편집**을 엽니다.
2. 내부에서도 블록 추가·연결·휠 확대·영역 선택·이동·복사·삭제·실행 취소를 사용합니다. 오른쪽 설정에는 최상위에서 사용 가능한 도구 및 자료가 이어집니다. JSON은 선택적인 고급 편집 방식입니다.
3. **입력 연결**에서 직접 연결된 앞 단계와 결과 항목을 선택하고 받을 자료형을 지정합니다. 알려지지 않은 MCP/Agent 결과 경로는 직접 입력할 수 있습니다. 목록의 `0` 경로는 예시이며, 결과 목록이 반드시 존재하거나 비어 있지 않다는 뜻은 아닙니다.
4. **출력 형식 선언**으로 `data.title`, `data.items.0.score` 등의 형식을 지정합니다. 이 설정이 데이터를 생성하거나 필수 존재를 보장하지는 않습니다. 실제 값이 있으면 실행기가 형식을 검사합니다. 완전한 필수 값 계약은 기존 JSON 스키마에서 설정할 수 있습니다.
5. **검증하고 상위 흐름에 적용**을 눌러 반영합니다. 취소하면 상위 정의는 바뀌지 않습니다. 순환 연결·중복 연결·잘못된 분기와 전체 중첩 예산은 적용 전에 검사합니다.
6. 오류 안내의 항목을 누르면 관련 블록을 선택하고 설정을 엽니다. 상위 목록의 중첩 오류는 해당 하위 흐름을 포함한 블록으로 이동하며, 하위 편집기 안에서는 내부 블록을 직접 선택합니다. 자료형 차이는 정적 경고이며 실제 실행에서도 검사합니다.

초안은 사용자·워크플로별 **현재 브라우저 탭**에 보관하고, 새로고침 뒤 명시적으로 복구합니다. 저장 원본이 바뀌었으면 새 사본으로 복구합니다. 서버 저장은 저장 버튼이 담당합니다. 적용 전 하위 편집 복사본은 초안에 포함되지 않으며, 페이지를 떠나려 하면 경고합니다. 브라우저 저장 공간을 사용할 수 없으면 수동 저장/JSON 보관을 안내합니다.

## 조합의 실행 범위

- 최상위와 각 하위 정의는 DAG입니다. 개별 정의 40개, 전체 120개 블록, 중첩 3단계의 기존 한도를 유지합니다.
- 병렬·작업 의존성·합치기·조건·승인·검토·보완 입력·메모리·복구는 실제 실행기 동작입니다. ‘수정 작업 반복’은 앞 방향으로 작성자와 검토자를 연결하거나 한도가 있는 작업 조정을 사용합니다. 목록 반복 블록을 임의 순환 그래프처럼 설명하지 않습니다.
- 임의 업로드 코드를 웹에서 실행하거나, 등록되지 않은 도구를 AI가 마음대로 만드는 기능은 제공하지 않습니다. 프로그램 블록은 등록된 연산을 실행합니다.
- 모든 조합의 성공을 보장하는 것은 아닙니다. 연결 구조가 유효해도 실제 모델 출력·도구 응답·업무 완료 조건이 맞아야 성공합니다. 미설정·검증 실패·승인 대기·불명확한 외부 변경 결과를 성공으로 표시하지 않습니다.

## 내보내기와 설정 위치

**AI 명령 프롬프트**는 내용 복사 전용입니다. 중첩 정의까지 실제 Agent가 있으면 Agent 다운로드를 준비하도록, 없으면 일반 실행 프로젝트를 준비하도록 안내합니다. 긴 내용은 20,000자 단위로 손실 없이 나눠 복사할 수 있고, 마지막 조각까지 받은 뒤 진행하라는 안내가 붙습니다. 글자 수는 모델 토큰 수가 아니며, 분할 전달이 외부 AI의 전체 입력 한도를 늘리지는 않습니다.

**Agent 다운로드**는 실제 Agent 블록이 있을 때 활성화됩니다. 문서만 제공하는 대신 설계 JSON, Agent.md, AGENTS.md, 선택한 Skill·MCP 정의, 두 언어 중 선택한 실행기, 고정된 Agent 진입점과 파일 검사 정보를 포함합니다. AI 문서는 설계와 같은 분기·입출력·대기·한도를 설명하며, 실행은 포함된 실행기로 수행하도록 안내합니다. 외부 AI 앱이 이 문서를 자동으로 인식한다거나 임의로 재해석해도 같은 결과를 낸다는 보장은 아닙니다.

| 대상 | 설정/명령 |
| --- | --- |
| 웹 | 도구 및 자료에서 MCP 정의·연결 ID·환경 변수 이름 등록. OpenAI 키 등록/호출 없음 |
| 내려받은 폴더 | `.env.example`을 `.env`로 복사. `OPENAI_API_KEY`, `FLOWLY_MODEL`, ZIP README의 `FLOWLY_MCP_ENDPOINT_…`·`FLOWLY_MCP_TOKEN_…` 설정 |
| 일반 Node.js | `node runner.mjs check`, `node runner.mjs run --input "요청"` |
| 일반 Python | `python runner.py check`, `python runner.py run --input "요청"` |
| Agent Node.js | `node agent.mjs check`, `node agent.mjs run --input "요청"` |
| Agent Python | `python agent.py check`, `python agent.py run --input "요청"` |
| 추가 Python 도구 | ZIP의 `PYTHON_TOOLS.md`, `tool-manifest.json`에 안내된 도구별 의존성·작업 폴더 설정 |

Agent ZIP의 로컬 운영 화면과 트리거도 같은 Agent 진입점을 사용합니다. 구성 파일이 바뀌거나 없어져도 일반 runner로 우회하지 않습니다. 키·토큰·테스트 응답은 ZIP에 넣지 않습니다. 내보낸 자료는 오프라인 복사본이므로 이후 원본 공유 철회가 이미 받은 복사본을 회수하지는 않습니다.

## 검증 기록

신규 사용자 조합의 상세 조건·명령·증거는 [USER_COMPOSED_VERIFICATION.md](USER_COMPOSED_VERIFICATION.md)에 기록합니다. **6개 설계 × 일반/Agent × Node.js/Python = 24 ZIP**을 실제 프로세스로 실행했고, **52개 시나리오 실행 + 24개 미설정 검사**를 통과했습니다. 모델·MCP HTTP 경계만 명시적인 대역으로 바꾸고 네트워크와 상위 자격 증명 전달을 차단했습니다. 입출력·병렬·분기·메모리·승인·재개는 실제 제품 실행기 코드입니다.

최종 소스의 전체 카탈로그 검사에서 **227개 그래프·454개 Node.js/Python ZIP·2,414개 검사**가 모두 통과했습니다. 현재 소스 지문·설계 해시·ZIP 해시와 일치합니다. 실제 OpenAI·원격 MCP 호출은 이번 작업 전체에서 **0회**입니다. 실제 모델 판단 품질·사내 서비스 호환성·운영 SSO는 이 로컬 검증에 포함되지 않습니다. 현재 검증 환경은 Windows, Node.js 26.5.0, Python 3.13.3이며 최소 지원 버전 전체 행렬 검사는 별도입니다.

검사 중 발견한 문제도 수정했습니다. 실행 중 교체되는 메모리/평가 값에는 이전 입력의 하위 필드 안내를 남기지 않습니다. 작업 의존 목록을 비웠을 때는 실제로 생성되지 않는 산출물 필드를 표시하지 않습니다. 고급 JSON의 아직 반영하지 않은 편집도 변경 확인 대상으로 포함합니다. 세 문제에는 각각 회귀 검사를 추가했습니다.

현재 확인한 브라우저 결과는 [편집기 QA](qa/editor-composition-qa.md)에 정리했습니다. 예제의 ‘병렬 분석’ 필터 48개와 ‘대표 예제’ 초기화 6개, 실제 블록에 따른 적응 안내, Agent 유무에 따른 다운로드 활성/비활성, Node.js/Python 프롬프트 진입점을 확인했습니다. 전체 **101,694자**와 분할 조각 **20,330자**를 실제 클립보드 내용과 대조해 일치함을 확인했습니다. 조각의 길이에는 전달 순서 안내가 포함됩니다. Python Agent ZIP 다운로드 성공 안내와 브라우저 오류 로그 0건도 확인했습니다.

초안 저장 상태 표시와 사용자별 직렬화·복구 로직은 검증했습니다. 다만 자동화 브라우저가 페이지 이탈 경고에서 새로고침을 취소하므로 **실제 새로고침 후 복구 버튼까지의 전체 UI 경로는 미확인**입니다. 이 항목을 브라우저 검증 완료로 집계하지 않습니다.
