# P2 · 등록 계산·검증 프로그램

2026-10-24. 모델이 계산 성공이나 검증 완료라고 말한 것을 그대로 완료 조건으로 쓰지 않도록, 모델·MCP 없이 실제 계산과 검사를 수행하는 `program` 노드를 추가했다. 한국어 화면 이름은 **계산·검증 프로그램**이다. 등록된 여섯 프로그램만 제공하며 사용자 코드·SQL·셸 명령·업로드 코드를 실행하지 않는다.

## 입력과 출력

```json
{
  "program": {
    "name": "numeric_summary",
    "arguments": {},
    "bindings": { "values": "data.values" }
  }
}
```

`arguments`는 고정 값, `bindings`는 노드에 전달된 입력의 점 구분 경로다. 같은 입력 이름에 둘 다 있으면 연결한 값이 우선한다. 없는 경로는 실행 실패로 처리한다. 전체 출력은 `{text: 정규화한 결과 JSON 문자열, data: 결과 객체}`다. 이후 조건 노드가 `data.valid`·`data.passed` 등을 평가할 수 있다.

| 프로그램 | 실제 동작 | 결과 |
| --- | --- | --- |
| `numeric_summary` | `values` 숫자 1~1,000개를 순서대로 합산. 선택한 `units`는 값 수와 길이가 같고 모든 단위가 같아야 함 | `count`, `sum`, `min`, `max`, `mean`, 선택 시 `unit` |
| `schema_check` | `data`를 기존 Flowly `schema`로 검사. 필수 값·배열 항목·허용되지 않은 추가 필드·정확한 자료형을 검사 | `valid`, `errors[{path,expected,message}]` |
| `schema_patch` | `data`, `schema`, `patches[{path,value}]`를 받아 현재 오류가 있는 **정확한 경로만** 수정하고 전체를 다시 검사 | 수정한 `data`, `valid`, `errors`, `appliedPaths` |
| `evidence_check` | `claims[{sourceId,version,quote}]`를 `sources[{resourceId,version,excerpt}]`와 대조. 동일 ID·버전과 비어 있지 않은 정확한 인용 부분 문자열을 요구 | `passed`, 주장별 `checks` |
| `goal_check` | `data`에 명시한 `checks`의 기존 조건 연산자를 평가. 빠진 값과 비교 불가능한 자료형은 통과하지 않음 | `passed`, 조건별 `checks` |
| `rank_fusion` | 여러 검색 순위에서 같은 자료 ID·버전·조각을 합치고 순위 역수 합으로 재정렬 | 출처를 보존한 `matches`, `count` |

스키마 검사 오류의 루트 경로는 빈 문자열, 필드·배열 항목은 `count`, `items.0.price` 형식이다. 루트 전체의 자료형이 잘못된 경우 루트 교체로 수정하지 않는다. 유효한 필드 수정·같은 경로 중복 수정은 거절한다. 수정 후에도 오류가 남으면 `valid:false`다. 추가 필드의 삭제, 새로운 스키마 제약, 자동 자료형 강제 변환은 포함하지 않는다.

계산은 Node.js와 일치하는 IEEE-754 부동소수점 연산이다. 통화 정산에 필요한 임의 정밀도 십진 연산이나 단위 변환 기능을 뜻하지 않는다. 무한대·NaN·참/거짓을 숫자로 계산하지 않으며 합계가 유한 범위를 넘으면 실패한다.

## 검색 순위 통합

`lists`는 배열 목록 또는 `{lexical:[...],vector:[...]}` 같은 이름별 목록이다. 이름별 목록은 이름 순으로 처리한다. 1~4개 목록, 각 목록 최대 100개 결과, `topK`는 1~10이다. `rankConstant`는 생략 시 60이며 0 초과 1,000 이하로 설정한다.

각 결과에는 `resourceId`, `version`, `chunkIndex`, `excerpt`가 필요하다. 선택된 `name`·`url`도 보존한다. 최종 점수는 목록별 `1/(rankConstant + 1부터 시작하는 순위)`의 합이다. 같은 목록 안의 중복 결과는 한 번만 가산하며, 점수가 같으면 자료 ID·버전·조각으로 결정한 고정 순서를 사용한다. 같은 자료 ID·버전·조각의 본문이 다르면 내용 충돌로 거절한다. 빈 검색 결과를 가짜 근거로 채우지 않는다.

이 프로그램은 등록한 검색 결과를 통합할 뿐 새로운 검색이나 임베딩 호출을 하지 않는다. 인용 검사는 근거 안에 같은 인용이 존재함을 확인하며 주장의 의미·논리·업무 정답률까지 보장하지 않는다.

## 실행 경계와 한도

- 프로그램 자체에는 네트워크·파일·프로세스 실행이 없다. Node.js 실행기에는 TypeScript 구현을 번들하고, Python ZIP은 프로그램 노드가 있을 때 `flowly_programs.py`를 포함한다.
- 입력은 유효한 JSON, 최대 200KB, 값 10,000개, 중첩 16단계로 제한한다. 스키마 깊이는 기존 규칙대로 8단계이며 한 번에 오류 200개, 수정 40개, 완료 조건 40개까지 처리한다.
- 주장·근거는 각각 최대 100개다. 빈 주장 목록·빈 완료 조건 목록은 완료로 처리하지 않는다.
- 오류는 실행기의 노드 오류 처리 정책을 따른다. 사용자가 `onError:branch`를 설정하면 연결한 오류 경로로 전달되며, 그렇지 않으면 실행이 실패한다.
- P1에서 생성한 AI 문서에도 실제 `program` 설정과 매핑이 포함된다. 문서만으로 프로그램을 흉내 내거나 성공을 선언하지 않는다.

## 검증

`node --import tsx --test tests/programs.test.ts tests/export-programs.test.ts` — **36개 통과**. 실제 Node.js·Python ZIP을 각각 풀고 여섯 프로그램의 성공·실패 16가지 사례를 실행했다. 완료한 실행의 재개에서 프로그램 노드가 중복 실행되지 않으며 두 언어의 결과 객체가 같음을 확인했다.

검사 사례: 실제 숫자 합계·평균, 혼합 단위·참/거짓·오버플로 거절, 잘못된 필드 정확히 식별, 정상 필드 보존, 부분 수정 후 재검증 실패 유지, 인용 ID·버전·본문 대조, 빈 인용 거절, 누락된 완료 조건 실패, 검색 통합 순위·출처 보존·중복 감점·내용 충돌 거절·빈 검색 결과. JSON 경로·임의 프로그램 이름·추가 입력·크기 한도도 검사했다. 변경 파일 ESLint 통과.
